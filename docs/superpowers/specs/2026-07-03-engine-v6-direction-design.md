## 0. 一句话结论

Engine System 已经把「项目记忆文件化」做到了同类玩法的天花板，但它的强制力金字塔是**倒立的**——最重的是 2430 行契约散文（agent 可能压缩、遗忘、跳过），最轻的是物理门禁（只看文件被 touch、平台覆盖有洞）。v6 的方向是把金字塔翻正：**agent 需要记住的东西缩到 ~400 行常数工作集，机器能校验的东西扩到覆盖每条关键规则**——规则从散文变成数据，记忆从平坦变成分形，架构师的控制从「读汇报」变成「拍决策」。这同时就是百万行代码库的答案：**每任务上下文 = f(任务)，而不是 f(仓库)**。

## 1. 问题定义：四个目标与它们的张力

| # | 目标 | 本质约束 |
|---|------|----------|
| G1 | 无编程经验者最大化可控 | 控制必须施加在**意图、行为、证据**上，不能要求读代码 |
| G2 | 高效持续开发 | 最小打扰、agent 高度自治——与 G1 的"处处确认"天然拉扯 |
| G3 | 百万行级代码库 | 任何单一上下文装不下全库；记忆必须空间分区 + 按需检索 |
| G4 | 对抗上下文漂移 | 防漂移机制**不能依赖 agent 自觉**（让漂移的人自证不漂移是循环论证） |

张力焦点：G1×G2 要求「默认自治 + 关键点硬停」；G3×G4 要求「工作集常数化 + 机器校验取代记忆」。四个目标的公共解只有一个：**把治理从 prompt 移进数据与代码**。

## 2. 现状诊断（证据驱动）

先说保留项——以下设计经审计确认是**真正的资产**，v6 全部继承：

- **知识六分类**（irreducible/derivable/mixed/index/anchor/generated-cache）——「CLI 下过期代码地图比没有地图更糟」是全系统最深刻的洞见
- **Plan + Spec Twin**（设计自由 + 验收可校验）与 acceptance evidence 门
- **吸收再指向**（用户手写规则先收编再恢复薄指针）
- **探查优先采访 + 双语分层 + PHASE 4 人话指南**（对 G1 的诚意设计）
- **三层兜底的概念**（A 锚点契约 / B git pre-commit / C 原生 hook）——概念正确，实现有洞（见 D1）

### D1 强制力金字塔倒立

| 层 | 体量 | 实际强制力 |
|----|------|-----------|
| 契约散文 | 2430 行 prompt + 2441 行 engine-init.md | 依赖 agent 读完并记住——上下文越长越不可靠，**恰是它要解决的问题** |
| Doctor | ~1070 行 sh+ps1 | 只查结构存在性（文件在不在、字段合不合法），不查语义 |
| Hooks | Stop + pre-commit | **「文件被 touch」门禁**：改一个标点即放行；改代码+只写 change capsule 反而被拦 |

已核验的具体缺陷：
1. 门禁与契约打架：AGENTS.md 要求写 capsule，Stop hook（`engine-hook-stop.sh`）只认 CONTEXT/HANDOFF/ENGINE_MAP 三文件——**v5.7 主打机制没接入 v5.6 门禁闭环**，Doctor 又把缺 capsule 记 WARN，三层标准互斥。
2. Windows 覆盖洞：`.claude/settings.json:10,22,27` 硬编码 `bash *.sh`，`.ps1` 副本存在但从不被引用——目标用户（中文小白）最可能的环境上 C 层整体哑火。
3. sh/ps1 语义分歧已实际发生：rename 场景 `.sh:39` 取旧路径、`.ps1:43-44` 取新路径；drift check 只比对同语言副本 SHA256，跨语言行为等价性无人守门。
4. 中文路径击穿解析：porcelain 输出遇非 ASCII 文件名会被 git 加引号（core.quotepath），`${line:3}`/`Substring(3)` 子串逻辑破功——对中文用户是高发路径。
5. contract migrator 无版本号：靠逐字节比对判幂等，BOM/空白差异即误判「需更新」。

### D2 记忆平坦 vs 代码库分形

ENGINE_MAP 是单一扁平注册表；PITFALLS 硬上限 500 行、CONTEXT 260 行、SPRINT 320 行。唯一空间分区手段是包级 README 锚点（>15 文件触发）——百万行库下会爆成上千锚点且无分层索引管理。超限唯一出路是「归档+指针」，但归档区**没有检索机制**：归档≈遗忘。规模假设停留在「agent 一次能装下大部分 irreducible 记忆」，对百万行不成立。

### D3 防漂移只守会话边界

现有手段（SessionStart 注入 / Stop 拦截 / 回写前 re-anchor / RECONCILE 对账）全部作用于**会话边界**。会话**中途**的漂移——长任务跑到一半上下文被压缩、agent 忘掉约束越界改文件——只有 read-gate 自报声明这一软手段，无任何机器校验。而中途漂移恰恰是大库长任务的主要失败模式。

### D4 架构师控制面是叙事不是结构

Change capsule 是**干活的 agent 自己写的散文自评**（SHOULD 级，可静默跳过）；强制暂停点靠 agent 自觉停；验收证据 Doctor 只查存在性。无编程经验者拿到的是「汇报」，不是「可执行的否决权」。沟通是单向的：agent 汇报→架构师读；缺一条结构化的**决策队列**让架构师像审批工单一样行使控制。

### D5 复杂度棘轮（契约单体膨胀）

v4→v5.7：prompt 1537→2430 行（+58%），记忆文件类型仅 8→11 类——**膨胀几乎全是治理规则**。每版新增带版本号的 Hard Rule、从不删旧内容；注册/生命周期/Doctor 规则在文内重复 3-4 遍；engine-init.md 完整复刻四个运维模式又各有独立命令文件（同一契约两份实现）；结尾横幅 v5.5 / 头部 5.7.0 / 上一版文件名 5.5 头部 5.6.0。**「单一真相源」是系统核心信条，唯独没对契约自己执行。** 每加一道硬闸都是对上一道软约定失效的自白——这个模式如果不打断，v6 会是 3000 行。

### D6 狗粮缺口

本仓库 dogfood 实例是自认的「MVP 精简版」：SYSTEM/PITFALLS/ARCHITECTURE 未生成、根锚点未铺、从未对自己跑过完整 `/engine-init`。卖「完整记忆层」，但完整形态在作者自己的项目上未被证明。

## 3. 北极星不变量（任何方案必须满足的可检验性质）

以下五条是 v6 的验收标准本身——每条都必须可被 Doctor/CI 机器判定：

| # | 不变量 | 判定方式 |
|---|--------|----------|
| N1 | **工作集常数化**：任一任务的常驻注入 ≤ 400 行（宪法+任务卡+所属域），与仓库规模无关 | SessionStart 注入行数计数 |
| N2 | **决策可追溯**：受保护路径的每次变更，都引用一个 approved 决策 ID | pre-commit / Doctor 校验引用链 |
| N3 | **完成有证据**：每个标 done 的 AC 都有可执行验证或架构师明示豁免 | 验证命令留痕 + 豁免=决策 |
| N4 | **规则即数据**：任何参与强制的规则，必须存在于门禁可消费的数据表中，仅存在于散文的规则不算数 | 「契约债」计数器（见 §7） |
| N5 | **自托管证明**：引擎仓库自身跑完整引擎、全绿通过自己的门禁 | check 脚本纳入发布门禁 |

## 4. 三条路线与权衡

### 路线 A · 硬化优先（修门禁，不动架构）

把每个已有承诺做成物理事实：门禁标准统一、Windows 覆盖、等价测试、中文路径、migrator 版本号、契约去重。
**得**：风险最低、立刻兑现 README 已承诺的可靠性、为一切后续奠基。**失**：不解决百万行，不解决棘轮。

### 路线 B · 分形优先（记忆架构升级）

域引擎 + 路由 + 预算 + 汇总协议 + 任务卡 + 决策台账。
**得**：正面回答 G3/G4，工作集常数化。**失**：若门禁仍是假的，漂移会在 N 个域上同时发生——**B 依赖 A 先行**。

### 路线 C · 平台化（引擎变成真软件）

CLI 守护进程/MCP server、数据库台账、向量检索、Web 驾驶舱。
**得**：能力上限最高。**失**：背叛「Just files, no runtime dependency」的立身之本；杀死 Web prompt 可移植性；bus-factor=1 养不起一个平台。

### 推荐：A → B 为主线，C 只取想法不取形态

顺序即论证：**门禁必须先诚实，再谈规模化**（否则规模只是放大谎言）。C 的想法（检索、驾驶舱）以「files+git 为底、零依赖为默认、可选加速器」的方式吸收。这也是对单人维护现实的尊重：每阶段可独立发布、可独立止损。

## 5. 目标架构：意图内核（v6 工作名）

核心翻转一句话：今天是「agent 被要求记住 2430 行，机器校验 ≈0 条语义」；目标是「agent 常驻 ~400 行，其余全部由机器按数据校验」。真相住在文件里（v4 遗产，保留），法律住在数据里（v6 变革），上下文按任务装配（v6 变革），架构师用决策治理（v5.7 的承诺，v6 使之强制）。

### 5.1 L0–L3 上下文装配层级（百万行的正面回答）

| 层 | 内容 | 体量 | 加载时机 |
|----|------|------|----------|
| L0 宪法 | Prime Directives + 决策边界 + 门禁说明 | ≤40 行 | 每会话常驻 |
| L1 任务卡 | 当前任务的目标/写集/禁区/AC/约束 | ≤20 行 | 常驻 + 压缩后重注入 |
| L2 所属域 | 任务落点域的 CONTEXT + PITFALLS 索引 + 锚点 | ≤300 行 | 按路由表装配 |
| L3 全局记忆 | 归档、跨域决策、全量 PITFALLS | 无上限 | **只按 ID/检索拉取，永不整体加载** |

会话装配 = L0+L1+L2 ≤ 400 行，**与仓库 1 万行还是 100 万行无关**。这就是 N1。WEB-FULL 同样受益：架构师只需粘贴「根摘要 + 一个域」，粘贴量恒定。

### 5.2 任务卡 Task Card（对抗会话中漂移的核心新原语）

`engine/tasks/T-NNN.md`，机读头 + 人话体，示例：

```markdown
# TASK CARD — T-047
> status: active | lane: L1 | decision: D-012 | plan: PLAN-03 | domain: auth
GOAL: 登录页支持微信扫码
WRITE-SET: src/auth/**, src/pages/login/**
FORBIDDEN: src/payment/**, prisma/schema.prisma
AC: AC-1 扫码后 3 秒内跳转首页 → verify: npm test -- auth/wechat
CONSTRAINTS: 不新增付费依赖 (source: SYSTEM Prime-3)
```

一个 ~15 行的工件同时命中四个目标：
- **G4 中途防漂移**：SessionStart(matcher: compact|resume) 重注入任务卡——漂移最危险的时刻（压缩后）恰好被打锚；Stop hook 校验 `git status` 触碰路径 ⊆ WRITE-SET ∪ engine 文件，**越界=机器拦截**，不再信 agent 自报。
- **G1 可控**：卡片是中文的、动工前生成并经架构师确认的；FORBIDDEN 就是架构师的否决权数据化。
- **G2 高效**：卡内即授权，agent 在写集内自治零打扰；出界必须回来变成一个问题/决策，打扰只发生在真正需要的点。
- **G3 规模**：卡片声明 domain → 决定 L2 装配什么，替代「读全库」。

Stop hook 语义升级（最小诚实版）：回写的 HANDOFF 追加行必须含当前任务卡 ID——grep 可查、语义有意义（回写与任务绑定）、实现廉价。

### 5.3 决策台账 Decision Ledger（架构师控制面数据化）

`engine/decisions/D-NNN.md`：

```markdown
# D-012 — 登录方式采用微信扫码优先
> status: approved | date: 2026-07-01 | expiry: none | scope: src/auth/**
选项: A 微信扫码(选定) / B 邮箱密码 / C 双轨
理由: 目标用户全在微信生态
后果: 需企业号资质; 海外用户暂不可登录
```

- 强制暂停点从「agent 自觉停」升级为**数据门禁**：受保护路径（schema、支付、部署配置……在 rules 表中声明）的变更，pre-commit 要求引用 scope 覆盖它的 approved 决策，否则拒绝提交。这就是 N2。
- `/engine-status` 顶部出现「**等你拍板**」队列（status: proposed 的决策，每条 2-3 选项+推荐+人话后果）——架构师的日常操作从「读汇报」变成「批工单」，这是 G1 的沟通通道从单向变双向的关键。
- 决策有 expiry 与 scope，RECONCILE 核对过期决策——决策也是会漂移的记忆。

### 5.4 分形域引擎 Domain Engines（空间分区 + 路由 + 汇总）

```
engine/
  ENGINE_MAP.md          # 根：宪法指针 + 联邦表（path-glob → domain）
  domains/
    auth/    {CONTEXT.md, PITFALLS.md, decisions/, tasks/}
    billing/ {...}
```

- **集中放置**（engine/domains/ 而非散落 src/*/.engine/）：Doctor/hook 实现保持单树遍历；代码侧的贴身触点继续由包级 README 锚点承担（两层各司其职）。
- **路由即 read-gate**：任务卡的路径 → 联邦表 → 唯一所属域 → L2 装配清单。read-gate 从「agent 自报读了什么」变成「路由表决定读什么」。
- **汇总协议**：每个域 CONTEXT 首行是一条预算内摘要，脚本提升到根 CONTEXT 仪表盘——根文件规模 = O(域数)，不是 O(仓库)。
- **ID 命名空间化**：auth/P012、billing/D003——PITFALLS 不再有全局 500 行天花板，每域自己的预算+归档+**检索配方**（rg recipe 登记在域索引，归档不再等于遗忘）。
- **域的划分来自产品而非代码**：INIT 采访加一问「你的项目分几大块？」——无编程经验者完全答得出产品分区（登录、商城、后台……），agent 负责映射成 path-glob 并用人话回确认。

### 5.5 契约编译 Compile, don't recite（拆掉棘轮）

契约单体拆为源模块 + 编译产物：

```
contract/src/     # 唯一真相源：知识分类.md, modes/*.md, rules/*.yaml(门禁规则表)
engine compile →  # 产出:
  dist/web-prompt.md      # WEB-FULL 全量（今天的 ENGINE_FILE_SYSTEM_v5.md）
  dist/runtime-law.md     # ~150 行常驻法（L0 的来源）
  dist/rules.json         # Doctor/hooks 消费的机读规则表
  plugin/.claude/commands/*.md  # 各命令文件（消灭 init.md 双份实现）
```

- check 门禁校验 `dist == compile(src)`——四处重复、版本横幅漂移、init.md/命令双份，一次性从根因消灭。
- **减法规则（反棘轮）**：契约源模块设字数预算，新增 Hard Rule 必须净零增长（删并等量旧散文），由 check 强制。规则的正确去处是 rules.yaml（机器执行），不是散文（agent 背诵）。

### 5.6 诚实门禁 Honest Gates

- **统一回写定义**：三层门禁共用 rules.json 里同一份「什么算回写」（含 change capsule——有意义变更时 capsule 从 SHOULD 升为门禁要求，G1 主打机制终于有硬保障）。
- **平台一致**：发一个 `engine-hook.cmd` 调度垫片（pwsh→powershell→bash 依序探测），settings.json 全平台指向同一入口——Windows 覆盖洞关闭。
- **等价测试**：fixtures/（含中文名、空格、rename 的 porcelain 样本）+ 期望裁决表，CI 对 sh/ps1 双实现跑同一夹具并 diff 裁决——rename 分歧这类 bug 整类消灭。porcelain 解析改用 `-z` 终止符，中文路径根治。
- **migrator 加 `contract-version:` 显式版本**，按版本号判迁移，不再逐字节比对。

### 5.7 架构师驾驶舱（/engine-status v2）

五段式，①–③纯数据确定性生成（不依赖 LLM 转述），④–⑤才由 agent 润色人话：
① 现在在干什么（lanes + 活跃任务卡）② **等你拍板**（决策队列）③ 最近完成 + 证据（capsule + AC 验证结果）④ 风险雷达（Doctor warning 人话版）⑤ 漂移警报。
**行为化验收**：AC 携带 `verify:` 命令，`engine verify T-047` 执行并把 PASS/FAIL+输出指纹写入 evidence/；UI 类 AC 用截图进 evidence/ ——无编程经验者判断不了代码，但**完全判断得了行为**。done 门 = verify 全绿 或 架构师明示豁免（豁免本身是一条决策）。这就是 N3。

## 6. 分阶段路线图（每阶段可发布、以自托管为验收）

| 阶段 | 内容 | 规模 | 自托管验收（狗粮） |
|------|------|------|-------------------|
| **S0 修门禁** | D1 五缺陷全修 + 契约四处重复收敛为一处附录 + 版本横幅 | 数天 | 本仓库三层门禁全真、check 全绿 |
| **S1 内核数据** | 任务卡 + 决策台账 + 门禁消费它们（写集校验/决策引用/capsule 入门禁）+ 压缩重注入 | ~1 周 | 本仓库后续开发全部走任务卡 |
| **S2 分形记忆** | 联邦表 + 域引擎 + 路由 read-gate + 汇总协议 + 检索配方 | ~2-3 周 | 对本仓库跑**完整** init（补 D6 缺口），并找一个真实大库试点 |
| **S3 契约编译** | contract/src 拆分 + compile + dist 校验 + 减法规则 | ~2 周 | prompt 由编译产出，人不再手改 dist |
| **S4 驾驶舱** | status v2 + 决策队列 + engine verify 行为化验收 | ~2 周 | 架构师日常只看驾驶舱即可决策 |

S0/S1 立刻兑现现有承诺；S2 回答百万行；S3 拆棘轮；S4 完成 G1 闭环。任一阶段后停下，系统都比前一天更诚实。

## 7. 度量：让改进可测

| 指标 | 现状 | 目标 |
|------|------|------|
| 每任务常驻注入行数 | 无界（随文件增长） | ≤400 恒定（N1） |
| 门禁漏拦/误拦 | 标点改动可骗过；capsule 被误拦 | fixture 回归=0 |
| capsule 覆盖率 | SHOULD，无统计 | 100%（门禁保证） |
| 受保护路径决策追溯率 | 0（无机制） | 100%（N2） |
| **契约债**：只存在于散文、无门禁背书的 MUST 条数 | ≈全部 | 每版递减（N4，Doctor 计数） |
| 契约同一规则出现处数 | 3-4 处 | 1 处 |
| 隔周恢复时间 | README 承诺 <5min | SessionStart 注入即达成，可测 |

「契约债」计数器让倒立金字塔本身变成一个可追踪下降的数字——用系统自己的哲学度量系统自己。

## 8. 明确不做的事（YAGNI）

- **不做**守护进程、数据库、Web 面板——files+git 仍是唯一底座，零运行时依赖是身份不是妥协
- **不做**向量检索（默认）——rg + 检索配方先行，用 miss 率数据证明需要后再谈（可选加速器位留好）
- **不扩**多 agent 并行机械——v5.5.1/5.5.2 尚未经真实多 agent 使用检验（bus-factor=1），冻结现状直到有真实使用者
- **不重写** sh/ps1 为单实现——等价测试养住双实现即可
- **不追**全 agent 生态 C 层适配——B 层（pre-commit）本来就是无关 agent 的最大公约数，把它做诚实优于给每家写适配器

## 9. 开放问题（需架构师拍板）

1. **路线确认**：A→B 主线（推荐）还是别的排序？

3. **门禁严格度**：写集越界默认「拦截」还是「警告+记录」？（推荐：禁区拦截、写集越界首次警告）

5. **capsule 入门禁的节奏**：S1 一步到位，还是先 WARN 一个版本再转硬？（推荐后者，给存量用户缓冲）
