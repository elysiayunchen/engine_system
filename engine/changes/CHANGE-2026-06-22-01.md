# CHANGE-2026-06-22-01 — Architect self-view and change capsules

> Created: 2026-06-22 · Status: verified · Related plan: none

## Goal
Make Engine System useful for non-technical vibe-coding architects by translating code and engine changes into reviewable project facts instead of raw diffs.

## Actual Changes
Added a change capsule workflow, Project Self-View guidance in status/reconcile, and Doctor checks for capsule completeness and acceptance evidence. Added an explicit SYNC migration mode plus executable `engine-migrate-contract.{sh,ps1}` scripts so existing projects that already have old engine files can absorb new mechanisms without rerunning init or overwriting project memory. Updated the initialization prompt, command templates, Doctor contract, README docs, installers, CLI shims, anchor sync scripts, and distributed agent bootloader wording.

## Impact Scope
Engine System tooling and documentation: initialization prompt, slash commands, contract migrator scripts, Doctor scripts, bundled plugin template, installers, CLI shims, cross-agent anchor sync scripts, README docs, and the dogfood engine contract.

## Risk & Watchpoints
The main risk is process friction: agents may now receive warnings when they change meaningful files without an architect-readable capsule. Contract migration also introduces managed blocks in old projects; those blocks must stay clearly marked so project-specific memory remains outside the managed region.
