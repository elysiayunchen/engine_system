## Goal
按架构师批准的 v6 路线执行第一阶段 S0:让"物理门禁说真话"。消除设计文档诊断出的四处门禁失真——sh/ps1 判定语义分歧、中文路径击穿解析、Windows C 层静默哑火、capsule 完全不入门禁——并给门禁本身配上机器背书(等价测试),而不是继续靠散文契约约束。

## Actual Changes
1. **Stop hook 双实现重写**(`plugin/engine/scripts/engine-hook-stop.{sh,ps1}` 及 `engine/scripts/` 同步副本):
   - 解析从逐行列位切换到 `git status --porcelain -z`(NUL 分隔):非 ASCII 路径在默认 `core.quotepath=true` 下不再被引号+八进制转义击穿;rename/copy 统一取新路径、跳过旧路径字段——修复 sh 取旧路径 vs ps1 取新路径的判定分歧。
   - capsule 进入门禁视野:改代码+回写记忆但无 `engine/changes/CHANGE-*.md` → 输出 `systemMessage` WARN(不拦截,按架构师拍板"先 WARN 一版");硬门禁(block)定义不变。
2. **pre-commit**(两份副本):`--name-only` → `--name-only -z | tr`,同一 quotepath 病灶的 B 层修复。
3. **engine-hook.cmd 调度垫片**(新文件,两份副本):Windows 上 `bash` 不在 PATH 时按 bash → Git for Windows bash.exe → PowerShell 孪生 逐级回退,消灭 C 层静默哑火。
4. **安装器**:`install.ps1` 生成的 hooks 改走垫片;`install.sh` 在 MINGW/MSYS 检测到旧式 `bash …` 命令时原地改写为垫片调度;两份 FILES 清单 + `plugin/manifest.json` 登记新垫片。
5. **contract migrator**(两份副本):managed 区块首行写 `<!-- contract-version: 5.7 -->`,Doctor/增量迁移从此可识别项目所载契约版本。
6. **等价测试**(新文件 `tests/hook-parity/run-parity.sh`):11 个真实 git 仓库场景(纯代码/回写无 capsule/全回写/纯引擎/中文路径/rename/防死循环/纯 capsule + pre-commit 3 场景),断言 sh 与 ps1 判定完全一致。
7. **契约横幅去重**(`ENGINE_FILE_SYSTEM_v5.md`):尾部横幅不再重复版本号(头部 5.7.0/尾部 v5.5 的漂移实证,按 N4"单一声明点"修正)。`plugin/.claude/commands/engine-init.md` 同一处修正因工具临时故障待补。
8. `.gitignore` 新增 `engine/.cache/`(generated-cache 永不入库)。

## Impact Scope
仅引擎工具层(hooks/安装器/迁移器/测试)。不触任何用户项目记忆文件的内容语义;硬门禁的拦截条件不变,新增的只有 WARN 通道。已装旧版的项目在下次 `engine update` + `/engine-sync` 后获得新行为。

## Risk & Watchpoints
- ps1 侧 `-z` 输出在 PowerShell 5.1 的编码行为依赖 `[Console]::OutputEncoding` 强制 UTF-8,极旧环境可能仍有非 ASCII 乱码——但判定按路径前缀匹配,乱码路径最多退化为"计入代码",不会漏拦(fail-closed 方向安全)。
- install.sh 的 sed 原地改写只针对本安装器铺设的命令形态,用户手改过的 settings.json 不受影响(匹配不上就跳过)。
- 垫片只覆盖新装/更新项目;存量项目的 settings.json 若从未重装,仍是旧命令形态。

测试过程抓出一个真实隐藏病灶并已修复:首次创建 `engine/changes/` 目录时,`git status --porcelain` 默认 `-unormal` 把整个未跟踪目录折叠成 `?? engine/changes/`,首个 capsule 被遮蔽,门禁看不见 → 改用 `-uall` 强制逐文件列出。这正是"门禁≠契约"诊断的活体实证:散文说"capsule 入门禁",但实现里默认 git 行为把它藏了,只有等价测试才暴露。

## Rollback
`git revert` 本提交即可整体回退;垫片与测试为新增文件,删除无副作用。已被 install.sh 改写过的用户 settings.json 手动把 `engine\scripts\engine-hook.cmd <name>` 换回 `bash engine/scripts/engine-hook-<name>.sh` 即恢复旧行为。
