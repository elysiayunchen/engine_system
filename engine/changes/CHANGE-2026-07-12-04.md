# CHANGE-2026-07-12-04 — engine/checks/ 自定义检查扩展点

## Goal
Doctor 的检查逻辑属于引擎共性,不应混入项目特化检查(如本项目三处 VERSION 一致)。需要给每个项目一个**不修改引擎本体**就能挂自定义检查的扩展点。

## Actual Changes
- **Doctor (sh + ps1)**: 新增 `run_custom_checks()` / `Run-CustomChecks` 函数,在所有内置检查完成后自动发现并执行 `engine/checks/` 目录下的脚本。
  - `check-*.sh|.ps1` → exit 非零 = FAIL
  - `warn-*.sh|.ps1` → exit 非零 = WARN
  - exit 0 = PASS,stdout 可选补充说明
- **本项目示例**: `engine/checks/check-version-consistency.{sh,ps1}` — 校验 `VERSION`、`engine/VERSION`、`plugin/VERSION` 三处一致
- **插件骨架**: `plugin/engine/checks/README.md` (使用说明 + 示例)
- **分发更新**: manifest.json / install.sh / install.ps1 新增 `engine/checks/README.md` 条目和目录创建
- **plugin 镜像**: `plugin/engine/scripts/engine-doctor.{sh,ps1}` 同步 custom checks 逻辑
- **ENGINE_MAP**: 运营工件层新增 `engine/checks/**` 条目
- **CONTEXT + HANDOFF**: 状态面板和会话历史更新

## Impact Scope
- **引擎面**: Doctor 新增 optional 发现逻辑,不影响现有检查
- **项目面**: 任何安装引擎的项目都获得 `engine/checks/` 空目录,可自建检查
- **本项目面**: 新增自动化检查,未来 VERSION 不一致会被 Doctor 发现

## Risk & Watchpoints
- 自定义脚本是任意代码执行——由项目开发者自行承担,引擎不做沙箱
- 非可执行文件会被 WARN (sh),PS1 版本只在 PS 环境运行

## Verification
- `bash engine/scripts/engine-doctor.sh` → custom check 出现在输出,三处 VERSION 均一致 PASS
- 0 FAIL / 1 WARN(契约负债,已有问题)
- PS1 版本独立测试通过

## Rollback
git revert,删除 `engine/checks/` 自定义脚本即可恢复旧行为。

## Responsibility Boundary
引擎层(Doctor 检查框架)与项目层(具体检查逻辑)职责分离。引擎只提供执行框架和约定,不管理项目自定义检查的内容。
