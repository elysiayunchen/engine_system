# CHANGE-2026-07-14-01 — VERSION 卡死 bug 修复 + Doctor 格式特征检测

## Goal
修复 `engine/VERSION` 在引擎源仓库中卡死的 bug(run_migrate 写入后 migrator 不更新已存在文件,导致 Doctor 循环 WARN 无法自愈),并在 Doctor 新增版本无关的格式特征检测,使老项目(如 study_engine)的 v5 数据残留能被检测和报告,同时对新用户零冗余。

## Actual Changes
- **migrator (sh + ps1)**: `engine/VERSION` 同步逻辑从 "create-if-missing" 改为 "always-sync"(源仓库:$ROOT/VERSION 存在时始终同步到 engine/VERSION;用户项目:保持 create-if-missing 遵守 P014)。always-sync 是幂等的(相同值则无副作用)。
- **Doctor (sh + ps1)**: 新增 `check_legacy_data_format()` / `Test-LegacyDataFormat` 函数,版本无关检测三类格式特征:
  1. 任务卡无 v6 header(无 `write-set:` 或 `status:`)
  2. `changes/` 有 capsule 但 `tasks/` 空(v5 数据残留)
  3. `evidence/` 有松散 `.md` 文件(v5 格式,非 T-NNN/AC-N.json)
- **migrator 结尾提示 (sh + ps1)**: 从固定文案 "Nothing extra" 改为条件化提示——检测到老格式残留时给出迁移指引,无残留时输出 "No further action needed"。
- **CONTEXT + HANDOFF**: 状态面板和会话历史更新。

## Impact Scope
- **引擎面**: Doctor 新增格式特征检测,版本无关,未来 v7 改格式时只需更新检测特征;migrator VERSION 同步逻辑修复。
- **项目面**: 老项目(有 v5 数据残留)跑 Doctor 会看到 WARN 指引;新项目(空数据)0 WARN,零冗余。
- **可持续性**: 不能"一劳永逸",但设计为可持续——每次迭代的成本是"改 5 行代码",复用现有机制(run_migrate + reconcile_schema + Doctor run_custom_checks),git history 承担考古层。

## Risk & Watchpoints
- check 只报告不修复——老数据保持原样,不自动转换(语义错位风险)。
- 检测逻辑是"格式特征"而非"版本号",任何老格式都会被检测,但需要未来 v7 发版时手动更新特征列表。
- always-sync 在源仓库中是幂等的,但在用户项目中保持 create-if-missing(P014:用户项目 $ROOT/VERSION 是产品版本,不是引擎工具版本)。

## Verification
- `bash engine/scripts/engine-doctor.sh` → 0 FAIL / 0 WARN(本仓库自检)
- `pwsh -File engine/scripts/engine-doctor.ps1` → 0 FAIL / 0 WARN(parity 确认)
- 空项目 fixture → 0 legacy WARN(对新用户零冗余)
- 老项目 fixture(3 份 CHANGE-*.md + 0 张 T-NNN.md)→ WARN 含 "change capsule" + "0 task cards"
- `bash scripts/check.sh` → CHECK PASSED

## Rollback
git revert,migrator 回到 create-if-missing,Doctor 删除 check_legacy_data_format 调用即可恢复旧行为。

## Next Step
提交推送。后续 v7 发版时,更新 Doctor check_legacy_data_format 的格式特征列表即可。

## Responsibility Boundary
引擎层(检测框架 + VERSION 同步逻辑)与项目层(具体数据是否需迁移)职责分离。引擎只检测和报告,不自动转换项目数据——迁移决策由项目开发者根据 WARN 指引自行决定。
