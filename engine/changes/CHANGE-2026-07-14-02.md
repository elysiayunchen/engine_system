# CHANGE-2026-07-14-02 — Doctor 补字节上限 + 单行宽度上限检查

## 目标

修复 Doctor 的盲点:现有行数上限(budget_cap)无法检测"单行膨胀"型异常。诺识项目 CONTEXT.md 仅 145 行但 317KB,状态面板表格单元格被空格填充到 19600 字符/行,分隔线 57735 字符,Doctor 报 0 failure。

## 实际变化

- `engine/scripts/engine-doctor.sh`: 行数检查后加字节上限(byte_cap = 行数 cap × 200)+ 单行宽度上限(2000 字符)
- `engine/scripts/engine-doctor.ps1`: parity 同步

## 影响范围

所有注册的引擎文件(ENGINE_MAP / CONTEXT / HANDOFF / SPRINT / PITFALLS / ARCHITECTURE / SYSTEM / ENGINE_DOCTOR / SOURCEMAP / AGENTS / CLAUDE)。用户项目跑 Doctor 时会自动检测膨胀。

## 风险

低。新检查报 WARN 不报 FAIL,与现有行数超限行为一致。阈值 2000 字符足够高,源仓库自身 0 误报(最长行 1125 字符)。

## 验证

- 源仓库:`check.sh` 全绿,Doctor 0 failure / 0 warning
- 诺识项目:Doctor 检测到 CONTEXT.md(317KB + 57735 字符行)、ENGINE_MAP.md(157KB + 10398 字符行)、HANDOFF.md(134KB + 5036 字符行)、SPRINT.md(4266 字符行)的膨胀
- 双实现 parity:.sh 和 .ps1 对相同文件报相同 WARN

## 回滚

删除 engine-doctor.{sh,ps1} 中 `# Byte budget` 和 `# Line width` 注释块下的两个 if 检查。

## 下一步

诺识项目需清理 CONTEXT.md / ENGINE_MAP.md / HANDOFF.md 的表格填充膨胀。
