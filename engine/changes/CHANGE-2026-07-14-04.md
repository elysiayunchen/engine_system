# CHANGE-2026-07-14-04 — Installer 下载失败聚合 + --local SHA256 校验

## 目标

修复 2026-07-14 发布端评估发现的两个安装缺陷(D-024/T-028):

1. 网络模式假成功:raw.githubusercontent.com 的 404 会把 "404: Not Found" 正文写进目标文件且 curl exit 0,`[[ -s ]]` 非空检查拦不住;runtime-law.md 段网络失败仅 skip 不报错。装出残缺环境却打印成功横幅。
2. --local 校验盲区:`verify_checksums` 只在 --version 网络路径生效,--local(唯一离线可靠路径,manifest.json 就在包里)完全跳过 SHA256 校验。

## 实际变化

- `install.sh`:
  - `download()` 改查 HTTP 状态码,非 200 删除残留文件并返回失败(触发既有 FAIL exit 1 路径)
  - runtime-law.md 下载后非空检查,失败 FAIL exit 1(原为静默成功打印)
  - --local 安装完成后用 `$LOCAL_DIR/manifest.json` 跑 `verify_checksums`,mismatch 硬失败
  - 新增 `WRITTEN_FILES` 写入清单:校验只针对本次实际写入的文件——被 keep/skip 的文件(根锚点 CLAUDE.md/AGENTS.md、既有 engine/*.md 记忆)与 manifest 不同是设计行为,不得误报
  - `verify_checksums` 的 src→dest 映射补 `engine/skeleton/*` 与 `VERSION` 两条(原映射错误导致这些条目永远查不到)
- `install.ps1` parity 同步:
  - `Copy-Local` 源文件缺失从 WARN 改为 FAIL exit 1(残包不装半截)
  - runtime-law.md 下载失败从 skip 改为 FAIL exit 1
  - -Local 模式用包内 manifest.json 跑 `Verify-Checksums`,mismatch exit 1
  - `$script:WrittenFiles` 写入清单 + skeleton/VERSION 映射,同 sh

## 影响范围

所有安装路径。--local/-Local 用户首次获得完整性校验;网络安装 404/网络故障从假成功变为硬失败。默认 main 分支安装仍不做 manifest 校验(manifest 与文件同源同 ref,只能检测传输损坏,已由逐文件状态码+非空检查覆盖)——此边界在代码注释中显式声明。

## 风险

低-中。写入清单作用域是新逻辑,若映射有漏,表现为"该校验的没校验"(回到旧行为)而非误拦。update 模式下被 protect 保留的文件不进清单,不会误报。
