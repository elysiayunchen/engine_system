# CHANGE-2026-07-17-01 — v6.5 长会话硬边界与并行记忆分片

> Created: 2026-07-17 · Status: verified · Related: D-025 / T-029

## Goal

解决两类可复现问题：约 200k 上下文模型长跑后遗忘任务范围、只剩提交门禁；并行 agent 在同一工作区抢写共享 CONTEXT/HANDOFF，互相制造冲突或代替对方满足写回。

## Actual Changes

- WRITE-SET/FORBIDDEN 覆盖全部项目路径（含 engine 文件），同时解析单行与 section-list 任务卡；active 卡格式损坏时 fail-closed。
- contract-version 6.5+ 无 active/closing 任务时，只允许创建任务卡/决策卡，普通写入由 PreToolUse、Stop、pre-commit 拦截；旧标记项目迁移前保留兼容模式。
- pre-commit 在任务置 `done` 时逐 AC 检查 PASS evidence；Doctor 同样检查每个 AC，但把成功的历史卡聚合为一行，只逐项输出失败。
- Claude UserPromptSubmit 重锚压缩到 4 行（上限 5 行），只保留任务 ID、GOAL、任务卡路径和并行归属，不重复 L0 或完整 WRITE-SET；写前边界由 PreToolUse 机械执行。
- PreToolUse 按 session_id + agent_id 记录声明写入路径；Stop 优先消费本 session 路径，Bash 等不可精确归属的写入保守回退全工作树。
- 新增 `engine workstream T-NNN <agent-id>`：worker 只写 `engine/workstreams/<task>/<agent>/CONTEXT.md|HANDOFF.md`，共享记忆由协调者在 merge point 一次汇总；代码物理隔离继续使用宿主 git worktree。
- 明确任务粒度：一张卡对应一个可独立验收、通常是 commit/PR 大小的目标；多轮消息和并行 worker 共卡，只读调查免卡，done 卡不注入 session context。
- sh/PowerShell、source/plugin、installer、manifest、migrator、contract managed block 和 agent-neutral pre-commit 同步发布；版本更新到 6.5.0。

## Impact Scope

影响 Engine System 的任务范围门禁、会话重锚、提交门禁、Doctor 输出、并行记忆协议、安装/迁移和发行镜像。不会接管 agent 进程调度或代码分支合并，也不会自动修改外部项目。

## Risk & Watchpoints

- v6.5+ 项目在没有 active 卡时会比旧版本更严格；升级后第一项写任务需先创建/激活卡。只读命令不受限制，任务/决策卡创建保留启动通道。
- Shell 工具无法可靠静态判断实际写入路径，PreToolUse 只打全局标记，Stop 采用保守检查；高并发代码修改仍推荐独立 git worktree。
- session 归属依赖宿主提供 session_id/agent_id；缺失时回退全工作树，正确性优先于减少误拦。
- exempt 仍是架构师逃生口；后续可进一步要求其引用 approved decision，但本次不改变历史卡兼容语义。

## Rollback

## Next Step

发布 v6.5 后，在至少一个真实下游项目运行 `engine update` + `engine migrate`，确认首次写任务会建立 active 卡、并行 worker 进入各自分片、done 提交要求 evidence。后续实现任务应新建/激活对应卡；只读评估无需建卡。
