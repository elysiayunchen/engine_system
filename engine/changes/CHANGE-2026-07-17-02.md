# CHANGE-2026-07-17-02 — v6.5.0 发布与远端更新链

> Created: 2026-07-17 · Status: pre-publish verified · Related: T-030 / D-025

## Goal

把已经通过 T-028/T-029 验收的 Engine System 6.5.0 发布到 `main` 与 `v6.5.0` tag，使下游 `engine check-update` 能看到远端 6.5.0，`engine update` 能拉到对应发布内容。

## Actual Changes

- 发布版本保持根 `VERSION`、`engine/VERSION`、`plugin/VERSION` 三处为 6.5.0。
- 补充 v6.5.0 CHANGELOG，包含全路径任务门禁、并行 workstream 分片、低 token 重锚和 done evidence 门。
- 将 T-028/T-029、D-024/D-025、验收 evidence、契约源/编译产物、plugin 镜像、installer 与测试一起提交。
- 推送 `main` 与 `v6.5.0` tag；GitHub `release.yml` 根据 tag 自动生成 tar/zip/offline 包、checksums 和 Release notes。
- 修复 CI/Release 的旧安装模拟：不再用 sed 绑定下载函数实现，统一调用正式 `install.sh --local plugin`。
- 将 plugin/AGENTS 收缩为薄引导器；fresh install + managed contract 后为 44 行，低于 45 行硬上限。
- `check.ps1` 在 GitHub Actions 中为每个失败项输出 `::error` annotation，避免无日志权限时只能看到笼统 exit 1。

## Impact Scope

影响 Engine System 发布仓库、GitHub Release、远端 raw `VERSION` 和下游 installer/update 拉取路径。`.workbuddy/`、`engine2.zip` 等用户 scratch 文件不进入提交。

## Risk & Watchpoints

- GitHub Actions Release 需要远端 tag push 后完成；若 workflow 失败，main/tag 仍可见但 GitHub Release 附件需重新运行 workflow。
- 下游 `engine update` 走 `main` 的 install.sh；`engine --version`/`check-update` 走 raw `VERSION`。两条路径必须同时指向 v6.5.0。
- 外部真实项目迁移尚未在本仓库内模拟；发布后应选一个下游项目执行 `engine check-update`、`engine update --check-only` 和 `engine migrate`。
