# CHANGE-2026-07-19-01 — v6.6.0 HANDOFF 历史归档机制

> Created: 2026-07-19 · Status: published · Related: T-031 / D-027

## Goal

把"HANDOFF.md 会话历史表只进不出"的慢性膨胀做成机制：契约源加 8 条上限 + 月度归档规则；Doctor 加条目数 WARN 检查；migrator 分发到旧项目；behaviors skill 加归档触发；当前仓做样本裁剪（53→8 条 + 月度归档文件）；CONTEXT.md「待验证」段已验证项一并清理。版本 6.5.0 → 6.6.0（minor，新增机制）。

## Actual Changes

### 契约源（contract/src/）

- `20-file-templates.md`：HANDOFF FILE 8「会话历史」表注解扩展——加「最近 8 条保留；超出 8 条时把最旧的整行迁移到 `engine/handoff-archive-YYYY-MM.md`（按月切分，文件名取被迁移条目的最早日期所在月）。归档文件不进 SessionStart 注入，只供按需搜索考古；不进 ENGINE_MAP §1 注册，Doctor 不校验其预算。」
- `30-operational.md`：RECONCILE 模式新增 8b 项——核对 HANDOFF 历史归档（条目数 > 8 时提示迁移最旧整行；归档文件不进 §1 注册；裁剪只迁移整行不删除内容）。
- `behaviors/handoff.md`：Step 4 扩展——追加新行后若历史表 > 8 条，把最旧的整行迁移到 `engine/handoff-archive-YYYY-MM.md`（按被迁移条目日期所在月命名）；归档文件 search-only，不进 SessionStart、不进 §1。Step 5 扩展——更新 CONTEXT 时删除「待验证」段中 `~~struck-through~~` 项。

### Doctor 实现（sh + ps1 双胞胎）

- `engine-doctor.sh`：新增 `check_handoff_history_cap()` 函数，awk 扫描 `## 会话历史` 段表格行数，> 8 时输出 WARN + human 解释；调用点紧跟 `check_handoff_semantics`。
- `engine-doctor.ps1`：新增 `Test-HandoffHistoryCap` 函数，逐行扫描等价实现；调用点紧跟 `Test-HandoffSemantics`。
- WARN 而非 FAIL：可能正当中断处理中，硬失败会卡住 agent；agent 下次写 HANDOFF 时按 behaviors/handoff.md step 4 触发归档。

### Doctor 契约（实例 + 模板）

- `engine/ENGINE_DOCTOR.md`（dogfood 实例）：「已注册的热路径记忆文件」行追加「会话历史表 ≤ 8 条（超出归档到 `engine/handoff-archive-YYYY-MM.md`，归档文件不进 SessionStart 注入、不进 §1 注册）」；managed block 新增 item 11。
- `plugin/engine/ENGINE_DOCTOR.md`（分发模板）：Required Checks 新增 #23——HANDOFF.md session history table ≤ 8 rows；older rows move to `engine/handoff-archive-YYYY-MM.md`（search-only，不进 §1，不进 SessionStart）；verified items in CONTEXT.md "to-verify" sections are removed。

### Migrator（sh + ps1 双胞胎）

- `engine-migrate-contract.sh` / `.ps1`：`doctor_tmp` managed block heredoc 新增 item 11——HANDOFF.md session history table keeps <= 8 rows；older rows move to `engine/handoff-archive-YYYY-MM.md`（search-only，不进 §1，不进 SessionStart）；verified items in CONTEXT.md "to-verify" sections are removed。
- 旧项目升级到 v6.6.0 后，下次 `engine migrate` 会写入新 managed block（contract-version 标记自动从 VERSION 文件读取为 6.6.0）。
- 不自动裁剪旧项目历史（避免 migrator 误删项目记忆）；裁剪由 agent 在下次写 HANDOFF 时按 behaviors/handoff.md step 4 触发——Doctor WARN 提示首次归档。

## Risk & Watchpoints

- 老项目升级到 v6.6.0 + `engine migrate` 后，Doctor 首次扫描会立即 WARN（历史 > 8 条）——这是预期信号，提示 agent 在下次写 HANDOFF 时执行首次归档。**不是 bug**，是机制触发信号。
- migrator 不自动裁剪旧项目历史——避免误删项目记忆。如果项目方希望保留更长历史，可主动忽略 WARN（Doctor 仍允许提交）。
- 归档文件命名按月切分：若一次迁移跨多个月份，会生成多个 `handoff-archive-YYYY-MM.md` 文件。这是预期行为，便于按月份搜索。
- HANDOFF.md「会话历史」表行数计算只认 `^\| YYYY-MM-DD \|` 模式；非日期化行不计入。表头/分隔行自动跳过。
- CONTEXT.md「待验证」段删除 ✅ 划线行的规则是契约级要求（behaviors/handoff.md step 5），不是一次性数据清理——下次 agent 写 CONTEXT 时也会按此规则执行。

## Rollback

若 v6.6.0 发布后发现归档机制误伤项目记忆（例如某项目依赖完整 HANDOFF 历史），可：
1. 从 git history 恢复被迁移的归档条目（commit hash 在 release commit 中）；
2. 把归档文件内容粘回 HANDOFF.md「会话历史」表；
3. 发布 patch 版本（如 v6.6.1）放宽上限或回退机制。

不回退 main 上已验收代码；下游仍可固定 v6.5.0 tag 安装避免新机制。
