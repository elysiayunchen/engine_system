# CHANGE-2026-07-19-03 — v6.6.3 hotfix

> source: D-028 §10 机制 A/B/C 挂载 AC-X.1 编号引入的副作用

## Goal

修复 `engine-verify.sh` / `engine-verify.ps1` / `engine-doctor.sh` / `engine-doctor.ps1` / `githooks/pre-commit` 共 5 个脚本(engine + plugin 镜像双份 = 10 处编辑,实际 8 处正则命中)的 AC id 解析正则只支持 `AC-<数字>` 格式、不支持 `AC-<数字>.<数字>` 子编号的 bug。

D-028 §10 机制扩展挂载了 AC-5.1 / AC-6.1 / AC-2.1 三个子编号 AC,若不修复,T-033/T-034/T-035 执行 `engine verify` 时会把 `AC-2.1` 误识别为 `AC-2`,导致 evidence 文件名错配 + done evidence 校验失败。

## Actual Changes

- **engine/scripts/engine-verify.sh:40** — sed 正则 `AC-[0-9]*` → `AC-[0-9][0-9]*(\.[0-9][0-9]*)*`
- **engine/scripts/engine-verify.ps1:52** — PowerShell 正则 `AC-\d+` → `AC-\d+(?:\.\d+)*`
- **engine/scripts/engine-doctor.sh:528** — sed 正则 `AC-[0-9][0-9]*` → `AC-[0-9][0-9]*(\.[0-9][0-9]*)*`
- **engine/scripts/engine-doctor.ps1:612** — PowerShell 正则 `AC-[0-9]+` → `AC-[0-9]+(?:\.[0-9]+)*`
- **engine/scripts/githooks/pre-commit:150** — sed 正则 `AC-[0-9][0-9]*` → `AC-[0-9][0-9]*(\.[0-9][0-9]*)*`
- **plugin/engine/scripts/** 全部 5 个镜像文件同步上述改动

## Impact Scope

- 不影响现有 `AC-N` 格式(向后兼容)
- 新增 `AC-N.M` / `AC-N.M.K` 多级子编号支持
- evidence 文件名:`evidence/T-NNN/AC-2.1.json` 直接用 ac_id 拼接,无需改动
- 用户项目:下次 `engine update` 下发后获得此修复
