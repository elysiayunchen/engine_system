# CHANGE-2026-07-23-01 — Issue #9 LF-only engine.ps1 PS 5.1 解析失败修复 (A+B 双保险)

> task: T-042 | decision: D-030 | version: v6.11.4 | date: 2026-07-23

## Goal

修复 GitHub issue #9 — `install.ps1` 产出 LF-only `engine.ps1`,PowerShell 5.1 解析 here-string 时行号错位导致 `Unexpected token '}'` 报错,`engine.cmd` shim 在仅有 PS 5.1 的 Windows 系统上完全不可用。方案 A(install.ps1 转 CRLF)+ 方案 B(engine.cmd pwsh 优先)双保险。

## Actual Changes

| 文件 | 变更 |
|------|------|
| `install.ps1` | 加 `Convert-ToCrlf` 辅助函数(L100-120);`Download-File`(release URL + raw URL 两处)和 `Copy-Local` 在 .ps1 落盘后调用,LF→CRLF 字节级转换 |
| `engine/bin/engine.cmd` | `where pwsh` 优先 → `pwsh -NoProfile -ExecutionPolicy Bypass -File`;fallback `powershell` |
| `plugin/bin/engine.cmd` | 同 `engine/bin/engine.cmd`(镜像) |
| `plugin/engine/bin/engine.cmd` | 同 `engine/bin/engine.cmd`(镜像) |
| `plugin/manifest.json` | `bin/engine.cmd` SHA256 更新:`c2c9ce91...430f8a` → `b618a219...c588f6` |
| `VERSION` / `engine/VERSION` / `plugin/VERSION` | 6.11.3 → 6.11.4 |
| `CHANGELOG.md` | 顶部追加 v6.11.4 段(完整 AC + 字节级根因证据) |

## Impact Scope

- 影响面:仅 install.ps1 行为(用户机器 .ps1 落盘后字节级转 CRLF)+ engine.cmd pwsh 优先检测
- `.gitattributes` 不变(D-015 policy `*.ps1 text eol=lf` 保留)— 仓库源继续 LF,转换只发生在用户机器
- manifest SHA256 兼容:`Get-NormalizedTextSha256` 已 strip CRLF→LF 再哈希,LF→CRLF 转换不破坏 manifest 校验
- PS1 对等性:本次未触及 .ps1 文件本身,3 个 engine.cmd 是 .cmd 镜像同步

## Risk & Watchpoints

- 低风险:方案 A 转 CRLF 只影响用户机器(install.ps1 写盘),仓库源保持 LF;checksum 已 normalize(strip CRLF→LF)兼容
- 方案 B pwsh 优先有 fallback `powershell`,不破坏无 PS 7 环境
- 字节级根因证据(颠覆 issue 描述):install.ps1 自身也是 LF-only(LF=464)且有 1 个 here-string(L264)却能跑完整个安装 → 证明 PS 5.1 对 LF-only here-string 解析 bug 是**累积性行号错位**(here-string 数量 + 首现位置决定何时炸),非 here-string 本身禁用;engine.ps1 有 3 个 here-string 首个在 L20 → 累积错位导致 183/268 报错(issue 报错行号是错位后的假行号)
- watchpoint:本地仓库 .ps1 换行符参差不齐(engine-verify.ps1 纯 CRLF、engine-doctor.ps1 混合、engine-context.ps1 纯 LF)→ 换行符从仓库源继承,非 install.ps1 统一转换;若后续新增 .ps1 含多 here-string,方案 A 已兜底
