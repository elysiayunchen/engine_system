# CHANGE-2026-07-23-02 — Issue #10 P038 parse_task_patterns 支持 YAML frontmatter 多行 write-set

> task: T-043 | decision: none (纯 bug fix) | version: v6.11.5 | date: 2026-07-23

## Goal

修复 GitHub issue #10 的 P038 — pre-commit `parse_task_patterns`(L35-77)两个解析分支(inline grep L37-41 + awk markdown L42-55)都不支持 YAML frontmatter 多行 `write-set:` 格式,导致用该格式的任务卡被误报「no readable WRITE-SET」拦截非相关 commit。扩展 awk 分支同时支持 markdown `## field` section + YAML frontmatter `field:` 多行列表 + 修复 case 敏感性 + frontmatter 边界检测。

## Impact Scope

- 影响面:仅 pre-commit `parse_task_patterns` 函数的 awk 分支解析逻辑(读任务卡 WRITE-SET/FORBIDDEN 字段)
- 兼容性:原 inline `WRITE-SET: a, b` 单行格式(inline grep 分支)不变,优先命中;原 markdown `## WRITE-SET` section 格式保留(改为 case-insensitive header 匹配);新增 YAML frontmatter `write-set:` 多行列表支持
- 行为变化:大写 `WRITE-SET` 调用现在能匹配小写 `write-set:` frontmatter 字段(原 case-sensitive 漏匹配,现 tolower 修复)
- 不影响 P037 legacy fallback(L89-94,留 T-044/D-032);不影响 protected_paths / worker mode / memory-written / done evidence 检查

## Risk & Watchpoints

- 低风险:awk 分支改动是纯增量(新增 frontmatter 分支),原 markdown section + inline 分支行为不变
- watchpoint:inline grep 分支(L37)仍 case-sensitive(`^${_field}:`),只匹配大小写完全一致的 inline 字段;case 不敏感只对 awk frontmatter/markdown 分支生效。pre-commit 调用恒为大写 `WRITE-SET`/`FORBIDDEN`,所以 inline `write-set:` 小写仍走 awk(由 awk tolower 兜底)。设计取舍:避免改 inline grep 的 case 行为(可能影响现有 case-sensitive 卡片解析语义)
- watchpoint:frontmatter 边界靠 `^---$` 检测;若任务卡用非标准 frontmatter 分隔符(如 `+++` TOML),不识别——但引擎任务卡格式约定 YAML frontmatter,非问题
- 字节级证据:reporter elysiayunchen 提供概念性 awk 补丁方向正确,但缺 case 敏感性 + frontmatter 边界检测两个细节(本 patch 补全)
