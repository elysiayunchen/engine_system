# CHANGE-2026-07-23-04 — T-045 CI environment multi-session isolation downgrade

> task: T-045 | version: v6.11.7 | decision: none (engine-runtime patch) | issue: GitHub Actions workflow red (CI environment)

## Goal

Fix GitHub Actions CI red — `engine-doctor.sh` `check_multi_session_isolation` and `engine-doctor.ps1` `Test-MultiSessionIsolation` hard-FAIL with "`.cache/sessions` dir missing" whenever contract-version ≥ 6.11.0. The `.cache/sessions` directory is a runtime byproduct of the SessionStart hook, which never runs in non-interactive CI environments (no agent session). The directory is also `.gitignore`d, so it is never created in CI — making every CI run red since v6.11.0 (10+ consecutive failures, runs 30007319625 / 30007325892 / 30007326022 etc).

When `$CI=true` or `$GITHUB_ACTIONS=true`, sessions-dir-missing degrades FAIL → WARN with the human hint "CI environment: SessionStart hook not expected to run, sessions dir absence is normal (cv=$contract_version)". Interactive environments unchanged (still FAIL when cv ≥ 6.11.0).

## Impact Scope

- **Affected environments**: GitHub Actions / GitLab CI / CircleCI / Jenkins / any CI that sets `CI=true`. The doctor check no longer hard-fails on missing `.cache/sessions` dir; degrades to WARN. Workflow turns green.
- **Unaffected**: Local interactive agent sessions (Claude Code, etc.) — unchanged. SessionStart hook still creates the dir; missing dir still hard-FAILs in interactive mode (legitimate signal that the hook didn't run).
- **Unaffected**: Other doctor checks. Only `check_multi_session_isolation` / `Test-MultiSessionIsolation` touched.

## Risk & Watchpoints

- **CI runs could mask real SessionStart hook breakage in interactive use**: If a future change breaks the SessionStart hook so that `.cache/sessions` is never created, CI will not catch it (only interactive sessions would). Mitigation: local interactive `engine-doctor` still FAILs — the gate is only relaxed for `$CI=true`, not globally.
- **Env var standard reliance**: Relies on `CI=true` (de facto standard across GitHub/GitLab/CircleCI/Jenkins). If a CI provider doesn't set it, `GITHUB_ACTIONS=true` covers GitHub specifically. Other providers can be added as needed.
- **Doctor check semantics shift**: The check now has two states — interactive (FAIL on missing) vs CI (WARN on missing). The check name and contract-level description are unchanged; CI downgrade is an implementation detail.
