# CHANGE-2026-07-23-06 — T-047 Windows PS 5.1 compat: non-ASCII in string literals

> task: T-047 | version: v6.11.8 | decision: none (engine-runtime patch) | issue: GitHub Actions CI Windows job red — "Windows PowerShell parser exited 6"

## Goal

Fix GitHub Actions CI Windows job持续红灯 — `check.ps1` 的 "Windows PowerShell compatibility" 步骤使用 `powershell.exe` (PS 5.1) 的 `Parser.ParseFile()` 解析所有 .ps1 文件。PS 5.1 对无 BOM 的文件使用系统默认 codepage (Windows-1252 on Windows Server US) 读取,而非 UTF-8。两个文件的**字符串字面量**含非 ASCII 字符,其 UTF-8 字节序列中包含 0x94 (Windows-1252 左弯引号 `"`),被 PS 5.1 误认为字符串终止符,导致 parse 失败:

1. **engine/bin/engine.ps1 L537**: `Write-Host "Flag file does not exist — multi-session lock already enabled."` — em-dash `—` (U+2014) UTF-8 = `E2 80 94`,byte 0x94 = `"` in Windows-1252。
2. **engine/scripts/engine-verify.ps1 L117**: `$header = "...AC 级压缩恢复锚点,见..."` — Chinese char `锚` (U+951A) UTF-8 = `E9 94 9A`,byte 0x94 = `"` in Windows-1252。
3. **engine/scripts/engine-verify.ps1 L122**: `$line = "...— evidence/..."` — em-dash `—` 同 #1。
