## Actual Changes

**A. engine verify 静默失效(engine-verify.sh/.ps1)**
- A-1:声明了 AC 但全部解析不出 verify 命令 → stderr 三行 parse-failure 说明 + exit 3(区别于 AC fail 的 exit 1)。原先输出 `0 pass, 0 fail, N skip` 看似"无事可做",实为解析失败(下游 18 张 done 卡零机器证据跑了 5 天)。
- A-2:verify 命令抽取改「首个分隔符切割」(`| verify:` 与遗留 `→ verify:` 两种野格式均收敛支持),命令体含字面 `verify:` 不再被贪婪匹配截断成碎片。
- A-3:AC id 正则放宽字母分组:`AC-A1` / `AC-B12` / `AC-1.2`(verify + doctor)。
- E-1(机器侧):可疑模式 WARN——命令自引用本卡 `engine/evidence/<id>/` 路径;全部 PASS 指纹皆空串 sha256。WARN 不改退出码。

**B. 解析统一(hook/pre-commit/doctor 三方对齐)**
- B-1:engine-hook-stop parse_task_patterns(sh+ps1)移植 T-043 三格式解析——只写 YAML frontmatter(规范格式)的卡不再被 PreToolUse 误报 "no readable WRITE-SET" 锁死全仓写入。
- B-2:doctor code→INVENTORY 检查换统一解析器(原 inline-only,对 section/frontmatter 项目从未评估过任何一张卡,独立于 contract-version 空转)。本仓启用后零违规(历史卡 inline 且已覆盖)。
- B-3:WRITE-SET 裸目录条目匹配子文件(`engine/evidence/T-049` 覆盖 `.../AC-1.json`),hook match_glob + pre-commit match_any_glob 加 `$p/*` 分支。
- 契约 00-core Task Card Rule 声明三拼法全解析器一致 + 裸目录语义。

**C. 自引用自锁**
- C-1:status 检测全站点改行首锚定 `^(> )?status:<state>`(sh 10 站点 + ps1 11 站点:hook-stop / session-start / context / pre-commit / engine bin / doctor)。原无锚全文 grep 把散文里引用该模式的 done 卡钉成 active → 全仓写入被锁(下游三次踩中;**本仓 T-049 卡自身 AC-5 描述文本也触发了一次,拦截消息出现「T-049, T-049」重复,现场实证**)。doctor 新增 `check_status_conflict`:同卡同时命中 active+done → FAIL。
- C-2:done 卡治理新提交——上游 v6.11.6(T-044/D-032)已修,本次仅在 issue 回复中说明。

**D. contract-version 绑定错误**
