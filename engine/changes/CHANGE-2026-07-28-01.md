# CHANGE-2026-07-28-01 - v6.12.2 tombstone 生命周期修复(SessionStart 不清理 + Doctor 误报 abnormal exit)

> Created: 2026-07-28 · Status: verified · Related: T-050 / D-035 · Supersedes: 无

## Goal

修复多会话 tombstone 生命周期的双重 bug,根本原因都是把「历史 transition 记录」当成「active 状态信号」治理。

- **Bug A**:SessionStart hook 在获取新 coordinator 锁时(fresh acquire / same-sid resume 两条路径)没有清理旧 tombstone,只有 `engine assume-coordinator` 命令做了清理。结果任何安静 24h+ 的仓库 Doctor 必 FAIL(本仓 tombstone `2026-07-26T22:16:57Z|1244|coordinator-exited` 36h 后触发 FAIL,实证)。
- **Bug B**:Doctor `check_multi_session_isolation` 把所有 >24h tombstone 报 "previous coordinator exited abnormally" 并 FAIL,但 `coordinator-exited` 是 Stop hook 写的**正常退出**标记;且契约 #17 原文已说 "triggers WARN",代码对 cv≥6.11.0 却 FAIL——契约/代码不一致。

修复原则:tombstone 是历史事件日志(已发生的 transition),不是 active problem 信号;真正的 active 状态在 lock file + lease mtime(已有检查)。

## Actual Changes

**A. SessionStart hook 清理 tombstone(engine-hook-session-start.sh/.ps1 + plugin 镜像)**
- A-1:fresh coordinator 路径(atomic 独占建锁成功)新增 `rm -f .cache/session.tombstone`——新 coordinator 上任 → 旧 tombstone 已无意义。对称 Stop hook 写 tombstone 的逻辑。
- A-2:same-sid resume 路径(同 sid 重入)同样清理——resume 会话上次 crash 后留下的 stale transition 记录已过时。
- A-3:stale-recovery 路径保持原行为(覆盖写 `stale-recovered` tombstone)——本就是正确的,不动。
- A-4:PowerShell 镜像同步:`Remove-Item ... .cache\session.tombstone -Force -ErrorAction SilentlyContinue`。

**B. Doctor tombstone >24h 改 FAIL→WARN(engine-doctor.sh/.ps1 + plugin 镜像)**
- B-1:新增 `tombstone_is_fail` 变量:cv ∈ [6.11.0, 6.12.2) 时为 1(保持旧 FAIL,迁移宽限),cv ≥ 6.12.2 时为 0(WARN)。
- B-2:WARN 消息明确 tombstone 是 historical transition record、lock + lease mtime 才是状态源、下次 coordinator 启动自动清理。删除 "exited abnormally" 误导性措辞。
- B-3:tombstone 类型解析(`cut -d'|' -f3`)写入消息(`type=coordinator-exited` 等),便于诊断。
- B-4:cv < 6.11.0 保持 advisory WARN(fail-open)。

**C. 契约 #17 同步(engine/ENGINE_DOCTOR.md + plugin/engine/ENGINE_DOCTOR.md)**
- C-1:contract-version 升 6.12.2。
- C-2:#17 Multi-session isolation 段重写:tombstone 是 historical transition records(NOT active-state signals);24h+ tombstone triggers WARN(auto-cleans on next coordinator start);SessionStart hook MUST 在 fresh coordinator acquisition 路径清理 tombstone。
- C-3:migrator sh/ps1 同步 managed block 模板到 6.12.2 内容。
- C-4:plugin/engine/ENGINE_DOCTOR.md(独立维护的源模板)item 29 同步重写,顶部加 `<!-- contract-version: 6.12.2 -->` 注释。

**D. 文档同步**

## Impact Scope

引擎运行时(SessionStart hook / Doctor)+ 契约文本(ENGINE_DOCTOR #17)+ 文档(ENGINE_FILE_SYSTEM_v5 / AGENT_ADAPTERS)+ migrator 模板。plugin 镜像同步;经 migrator 分发下游。行为向后兼容:cv < 6.12.2 项目保持旧 FAIL 行为(迁移宽限期)。

## Risk & Watchpoints

- **Doctor 降级 FAIL→WARN 的诊断信号减弱**:cv ≥ 6.12.2 项目 >24h tombstone 不再阻塞 Doctor。但 tombstone 本就不是 active 状态信号——真正的 active 状态问题由 lock file + lease mtime 检查(已有,FAIL 级)覆盖。如果未来发现 tombstone 高频出现是真问题(本不是),Doctor 已有 `check_multi_session_isolation` 框架可加 tombstone 频率 WARN。
- **SessionStart 清理 tombstone 掩盖 Stop hook 故障**:如果 Stop hook 异常退出不写 tombstone,SessionStart 清理路径不会发现「上次没写」。但这本就是 tombstone 的设计——它不是必须存在的事件日志,缺失不构成问题。
- **WSL 测试环境坑**:PowerShell hook 测试需通过 WSLENV 转发 CLAUDE_PROJECT_DIR(WSL→Windows 进程不传任意 env var),已在测试中处理。
