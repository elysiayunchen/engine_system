# CHANGE-2026-07-28-02 - v6.12.3 pre-commit dist-stale 门禁

> Created: 2026-07-28 · Status: verified · Related: T-051 / D-035 · Supersedes: 无

## Goal

防止再次发生「编辑契约源/编译产物却没跑 `bash contract/compile.sh`」导致 CI Doctor `contract dist is not compile(src)` FAIL。v6.12.2 发版时实证:ecea136 直接编辑 `ENGINE_FILE_SYSTEM_v5.md`(编译产物)未更新 `contract/src/30-operational.md`(源)也未跑 compile.sh → Doctor FAIL → CI/Release 双红 → 不得不 re-tag(033a32a)。

修复原则:在 pre-commit hook 加前置防线,工作树 dist 与 compile(src) 不一致就拦下来,把缺陷挡在 commit 之前。无契约文件 staged 时零开销跳过;compile.sh 自身失败时 fail-open WARN(CI Doctor 仍兜底)。

## Actual Changes

**A. pre-commit hook 加 dist-stale 门禁(engine/scripts/githooks/pre-commit + plugin 镜像)**

- A-1:触发条件——staged 含 `contract/src/**` 或 6 个 dist 文件之一(`ENGINE_FILE_SYSTEM_v5.md`/`runtime-law.md`/`rules.json`/`plugin/.claude/commands/engine-init.md`/`engine/prompts/init.md`/`plugin/engine/prompts/init.md`)。
- A-2:检测逻辑——`mktemp -d` 创建临时目录,`ENGINE_COMPILE_OUT=$tmp bash contract/compile.sh` 编译到临时目录,diff 6 个 dist 文件的工作树版本与编译输出。
- A-3:FAIL 行为——任一文件不匹配 → exit 1,stderr 消息含 `Contract dist is stale: <files>` + 提示 `bash contract/compile.sh`。
- A-4:零开销——无契约文件 staged 时跳过(return 0)。
- A-5:fail-open——compile.sh 自身失败时 stderr 输出 WARN,不拦 commit(不阻塞无关 commit;CI Doctor 仍兜底)。
- A-6:plugin 镜像 byte-identical。

**B. 测试 `tests/workstream/test_precommit_dist_stale.sh`(5 场景)**

- B-1:S1(AC-2) 源改未编译 → FAIL。
- B-2:S2(AC-3) 直编 dist → FAIL。
- B-3:S3(AC-4) 源改 + 编译 → PASS。
- B-4:S4(AC-1) 无契约文件 staged → PASS(skip)。
- B-5:S5(AC-5) compile.sh 失败 → WARN(fail-open)。

**C. 版本 + CHANGELOG + manifest**

- C-1:VERSION×3(root / engine / plugin)→ 6.12.3。
- C-2:CHANGELOG v6.12.3 段:背景、机制(FAIL/skip/WARN)、测试场景。

## Impact Scope

pre-commit hook + plugin 镜像 + 测试套件 + 版本/CHANGELOG/manifest。不修 compile.sh 本身;不修 Doctor 已有的 `contract dist is not compile(src)` 检查(pre-commit 是前置防线,Doctor 是 CI 兜底)。不修 contract/src(预算不动);不修契约文本。plugin 镜像同步;经 migrator 分发下游(无 contract-version 变化,无迁移需求)。

行为变化:任何 staged 含契约源或编译产物的 commit 现在会被 pre-commit 检查工作树 dist 是否新鲜。源改未编译 / 直编 dist 两种误用被拦。零开销 for 非 contract commit。compile.sh 失败时 fail-open。

## Risk & Watchpoints

- **比较工作树 dist 而非 staged dist**:覆盖最常见的两种误用(源改未编译 / 直编 dist)。staged-only 检查需 `git show :path`,复杂且慢;工作树检查更简单且覆盖主要 case。极端边界:工作树 dist 已更新但 staged dist 未 stage → 工作树检查 PASS,commit 后仍可能 dist stale——但 `git commit` 会 stage 当前工作树内容,所以这种边界实际不存在。
- **compile.sh 失败 fail-open 的诊断减弱**:compile.sh 自身故障不阻塞 commit。但 CI Doctor 仍兜底检查 `contract dist is not compile(src)`,且 compile.sh 故障会立即在 Doctor 显示。fail-open 选择是为不阻塞无关 commit(可能 compile.sh 在某环境临时不可用)。
- **临时目录清理**:`mktemp -d` 创建的临时目录在检查完成后 `rm -rf` 清理。FAIL 时也清理(在 return 1 前)。
- **PowerShell engine-verify 在 TRAE 环境失效**:TRAE IDE `safe_rm_aliases.ps1` 包装 `Remove-Item Env:VARNAME` 不识别 `Env:` drive prefix,在 `$ErrorActionPreference = "Stop"` 下抛 terminating error 被 trap 捕获,导致 `engine verify` PowerShell 版本对所有 task 都报错。bash 版本正常。本 bug 不在 T-051 scope(超出 WRITE-SET),留待独立任务修复。
