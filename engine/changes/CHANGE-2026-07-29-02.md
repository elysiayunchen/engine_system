> Created: 2026-07-29 · Status: verified · Related: T-053 · Supersedes: 无

## Goal

预防性修复 `engine-verify.ps1` 行 107 的 `Remove-Item Env:ENGINE_VERIFY_RECURSE_GUARD -ErrorAction SilentlyContinue`。T-051 CHANGE 行 47 记录:TRAE IDE 的 `safe_rm_alias.ps1` 包装 `Remove-Item`,不识别 `Env:` drive prefix,在 `$ErrorActionPreference = "Stop"` 下抛 terminating error 被 trap 捕获 → exit 1 → 任何 task verify 报错。

当前 TRAE 环境 bug 不复现(疑似 `safe_rm_alias.ps1` 已修),但作防御性编程改用 .NET 原生方法,永久消除该类风险。

## Actual Changes

**A. engine-verify.ps1 行 107 修复(engine + plugin 镜像)**

- A-1:`Remove-Item Env:ENGINE_VERIFY_RECURSE_GUARD -ErrorAction SilentlyContinue` → `[Environment]::SetEnvironmentVariable('ENGINE_VERIFY_RECURSE_GUARD', $null, 'Process')`。
- A-2:.NET 原生方法完全绕过 PowerShell provider 机制,不被任何 alias 包装影响。
- A-3:在 PS 5.1/7+ 行为一致;`'Process'` scope 与原 `Env:` provider 语义一致(只清当前进程)。
- A-4:plugin 镜像 byte-identical。

## Risk & Watchpoints

- **bug 当前不复现**:T-051 CHANGE 记录的 bug 在当前 TRAE 环境不复现。可能 TRAE 已更新 `safe_rm_alias.ps1` 修复了 `Env:` drive prefix 识别。本次为预防性修复,防止 TRAE 未来回退或其他环境复现。
- **.NET 方法与 Remove-Item Env: 语义等价**:`[Environment]::SetEnvironmentVariable('VAR', $null, 'Process')` 与 `Remove-Item Env:VAR` 在清除进程级环境变量上行为一致。`$null` 在 .NET API 中表示删除变量,不是设为空字符串。
- **不影响递归守卫逻辑**:递归守卫的设置(行 98 `$env:ENGINE_VERIFY_RECURSE_GUARD = $Task`)和检查(行 32-34)未改动,只改清除方式。
