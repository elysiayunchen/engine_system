# CHANGE-2026-07-29-03 - v6.14.0 pre-commit done-card drift

> Created: 2026-07-29 · Status: verified · Related: T-054, issue #18 · Supersedes: 无

## Goal

修复 pre-commit hook AC PASS 检查(L260-287)对所有 staged done 卡运行、不区分「active→done 转换」与「已 done 卡修改」的问题。bookkeeping 任务修改已 done 卡的 verify 命令后,re-verify 产生 content-drift FAIL(VERSION bump、revision 变化、progress.md 归档等),锁死提交,被迫 `--no-verify` 绕过(连带丢失 WRITE-SET/FORBIDDEN/protected/dist-stale 门禁)。

## Actual Changes

**A. pre-commit hook L273-279 加 HEAD status 比较(engine + plugin 镜像)**

- A-1:AC PASS 检查前加 `head_task_snapshot="$(git show HEAD:$task_path)"` + HEAD status done 检查。HEAD=done → `continue` 跳过(已 done 卡修改,非转换)。
- A-2:HEAD=active → 不匹配 done → 检查 AC PASS(active→done 转换,正确)。
- A-3:HEAD 缺失(新卡)→ `git show HEAD:` 返回空 → 不匹配 done → 检查 AC PASS(新卡首次 done,正确)。
- A-4:exempt marker 在 HEAD 检查之前(L267),仍被尊重,逻辑不变。

**B. 测试**

- B-1:`tests/workstream/test_precommit_done_card_drift.sh` 5 场景:active→done 检查 / 新卡首次 done 检查 / 已 done 修改跳过 / exempt 跳过 / 非 done 跳过。

## Impact Scope

- pre-commit hook AC PASS 检查块(L260-287):行为变更,已 done 卡修改不再检查 AC PASS。
- WRITE-SET/FORBIDDEN 门禁(L228-255):独立代码路径,不受影响。
- protected-path 检查(L289-343):独立代码路径,不受影响。
- dist-stale 门禁(L353-387):独立代码路径,不受影响。
- exempt marker 逻辑(L267):不变。

## Risk & Watchpoints

- **风险**:已 done 卡修改跳过 AC PASS 后,如果修改了 AC verify 命令本身(如从 `grep 6.12.1` 改成 `grep 6.14.0`),新 verify 命令不会被 pre-commit 验证。缓解:这属于 bookkeeping 修改,verify 命令修复后 re-verify 产生新 evidence,doctor 仍检查 evidence 存在性(只是 pre-commit 不拦)。
- **watchpoint**:active→done 转换仍被严格检查,这是核心安全语义,不变。
