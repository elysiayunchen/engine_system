# CHANGE-2026-07-29-09 - v6.16.0 doctor 一致性对齐(#19 + #20)

> Created: 2026-07-29 · Status: verified · Related: T-060 · Supersedes: 无

## Goal

修复 GitHub issue #20 [D-17] 与 #19 [D-16] 两个 doctor 行为一致性缺陷:

- #20: migrator 模板 item 17 单行 2473 字符,违反 doctor 自己的 `check_long_line` (max 2000),导致 doctor 永久 1 WARN 无法清除;用户手工拆分后,下次 `engine migrate` 又会用单行模板覆盖回去。
- #19: doctor 对 HEAD 已有的 done 卡(非本次 active→done 转换)误报 FAIL "done without complete PASS evidence";pre-commit hook v6.14.0 (T-054) 已对齐跳过,doctor 未对齐,导致本地 doctor 与 hook 行为不一致。

## Actual Changes

**A. migrator item 17 长行拆分(修复 #20)**

- `engine/scripts/engine-migrate-contract.sh` 与 `.ps1`(+ plugin 镜像):item 17 managed block 模板从单行 2473 字符拆为 1 主行 + 6 子项 markdown bullet,每行 ≤800 字符。
- 拆分后内容语义等价(原 2473 字符单行涵盖 pid/tombstone/SessionStart/PreToolUse/task-gating/migration-grace 6 个子主题,拆分后每个子主题独立 bullet)。
- 用户项目运行 `engine migrate` 时,新生成的 `ENGINE_DOCTOR.md` item 17 自动是拆分形态,不再覆盖手工修复。
- `engine/ENGINE_DOCTOR.md` 与 `plugin/engine/ENGINE_DOCTOR.md` 通过 `engine migrate` 重新生成,验证 `awk 'length>2000'` 返回 0 行。

**B. doctor HEAD 检查降级(修复 #19)**

- `engine/scripts/engine-doctor.sh` 与 `.ps1`(+ plugin 镜像):`check_task_card_done_evidence` 函数在原 FAIL 分支前新增 `elif` 分支,用 `git cat-file -e "HEAD:engine/tasks/$tid.md"` 检测卡是否预先存在于 HEAD。
- 预存在(HEAD 已有此 done 卡)→ 降级为 WARN "task $tid (pre-existing in HEAD) done with AC evidence drift - legacy card, run 'engine verify $tid' or mark exempt"。
- 不预存在(本次新转 done)→ 保持原 FAIL,确保新卡必须带完整 PASS 证据。
- 行为对齐 pre-commit hook v6.14.0 (T-054 issue #18) 的 "HEAD-status diff" 逻辑。

**C. 版本同步**

- `VERSION` / `engine/VERSION` / `plugin/VERSION`:6.15.1 → 6.16.0
- `AGENTS.md` / `engine/SYSTEM.md` / `engine/ENGINE_DOCTOR.md` managed block 戳:contract-version 6.15.1 → 6.16.0
- `plugin/manifest.json`:62 条目 SHA256 重算(因 engine-doctor.{sh,ps1} + engine-migrate-contract.{sh,ps1} 内容变化)
- `engine/HANDOFF.md` 立即恢复点更新到 v6.16.0

## Impact Scope

- doctor 行为:对 HEAD 已有 done 卡的 FAIL → WARN(不阻塞,提示重验证或标记 exempt)。
- migrator 输出:managed block item 17 多行格式(向后兼容,已存在的 managed block 在下次 migrate 时被新模板覆盖)。
- 不影响:pre-commit hook(已是 v6.14.0 行为)、engine-verify、新 done 卡的严格 FAIL。

## Risk & Watchpoints

- **风险 A**:`git cat-file -e HEAD:...` 在 shallow clone / 无 git 环境下不可用 → 退化为原 FAIL 行为(`command -v git` 与 `git cat-file` 双重守护,失败时落 else 分支)。已测试无 git 环境保持原 FAIL。
- **风险 B**:migrator 模板变化可能让用户项目 diff 噪声变大(item 17 从 1 行变 7 行)。语义无变化,接受。
- **风险 C**:降级为 WARN 后,真正漂移的 done 卡可能被忽视。WARN 文案明确提示 "Re-verify or mark exempt",且不消除原 PASS 证据缺失事实,只是不阻塞。
