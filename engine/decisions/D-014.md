# D-014 — 自动更新与迁移机制设计

> status: approved | scope: engine/decisions/**, engine/tasks/**, engine/scripts/**, plugin/engine/scripts/**, engine/bin/**, plugin/bin/**, engine/migrations/**, plugin/migrations/**, install.sh, install.ps1, plugin/manifest.json, plugin/AGENTS.md, plugin/.claude/commands/engine-sync.md, scripts/**, VERSION, engine/VERSION, plugin/VERSION | expiry: never | supersedes: none | related: D-013

## 背景

v6 体系已完善(N1-N5 机器强制),但更新/迁移机制停留在 v5.7:
- `engine update` 只拉取文件,不检测版本、不自动迁移、不验证
- `engine-migrate-contract` 只写 v5.7 contract block,不创建 v6 数据层(任务卡/决策台账/联邦表/evidence)
- 无 VERSION 文件(版本号散落在 ENGINE_FILE_SYSTEM_v5.md:3 与 migrator 硬编码 5.7)
- session-start 不提示更新

用户要求:①自动检测更新 ②老项目完整更迭到 v6 所有机制 ③远程拉取自动更新。

## 决策

### D-014.1 版本号权威源 = 仓库根 VERSION 文件
- 新增 `VERSION`(仓库根,单行 `6.0`);install 时复制到 `engine/VERSION`(本地印记)
- 本地版本:优先读 `engine/VERSION`,回退解析 `ENGINE_FILE_SYSTEM_v5.md` 的 `Version:` 行
- 远程版本:`https://raw.githubusercontent.com/elysiayunchen/engine_system/main/VERSION`
- **Why**:单一真相源,可 curl 可 cat,与 install.sh 同源;manifest 是安装清单(混版本号语义不清),git tag 是发布点非开发版本(当前无 tag)
- **Alt rejected**:manifest.json 加 version 字段;git tag

### D-014.2 检测时机 = 手动 + 自动温和提示
- `engine check-update` 子命令:curl 远程 VERSION 对比本地;exit 0=最新 / 7=有更新 / 8=网络错
- session-start hook 温和提示(非阻塞,fail-open,24h 缓存 `engine/.cache/update-check.json`)
- **Why**:手动可精确查询;自动不扰民(缓存避免每次 session 联网,fail-open 保证离线可工作)

### D-014.3 迁移机制 = 增强 migrator + 版本化 steps 框架
- 增强 `engine-migrate-contract`:CONTRACT_VERSION 读 VERSION(6.0);managed block body 更新到 v6 内容(任务卡/决策台账/联邦表/三层门禁/契约编译/驾驶舱/N1-N5);新增结构创建段(目录 + federation.json + rules.json)
- 版本化 steps:`plugin/migrations/v6.0.{sh,ps1}`(结构创建逻辑),migrator 编排调用;未来版本追加 step
- `engine migrate` 子命令:单独可跑(修复/重试)
- **不在用户项目创建 `contract/`**:契约编译是引擎开发期工具,用户项目的契约通过 managed block 体现
- **不强制升级已有任务卡格式**:创建模板,不破坏现有
- **Why**:migrator 已是 idempotent block upsert,扩展为「block + 结构」最小改动;版本化 steps 支持未来渐进迁移(v6.1/v7)

### D-014.4 更新流程闭环 = 一站式 + 选项
- `engine check-update`:检测
- `engine update`:增强为 拉取 → migrate → doctor 一站式(加 `--check-only`/`--no-migrate` 选项)
- `engine migrate`:单独跑迁移
- **Why**:CONTEXT.md 旧假设「engine update 只负责工具分发」已过时;一站式降低认知负担,选项保留细粒度控制

### D-014.5 远程自动更新链 = 复用 install.sh 分发
- `engine update` 从 GitHub main 拉取 install.sh --update(已存在),增强后自动 migrate + doctor
- 整链:curl VERSION 检测 → curl install.sh 拉取 → install 铺最新 migrator → migrator 应用 v6 结构 + block → doctor 验证 → 更新 engine/VERSION
- **Why**:复用现有 install.sh 分发基础设施,只加版本检测 + 自动 migrate/doctor 闭环

## 不做的事
- 不做后台守护进程/定时任务(用户主动 `engine update` 或 session-start 提示后手动)
- 不做差量更新(全量 install.sh --update 已足够,差量复杂度高收益低)
- 不做自动 push/PR(只更新本地,提交由用户/架构师决定)
- 不迁移 contract/ 到用户项目(开发期工具)
