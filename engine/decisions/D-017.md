# D-017 — 发布端方向（面向任何 AI 辅助开发者）

> status: approved | scope: plugin/**, install.sh, install.ps1, scripts/**, contract/**, engine/tasks/**, engine/decisions/**, engine/changes/**, engine/CONTEXT.md, engine/HANDOFF.md, package.json, .github/** | expiry: never | supersedes: none | related: D-014

## 背景

v6 体系（S0-S4）全部落地，PR #8 已合 main（v6.0.1）。引擎内部成熟度很高，但「最后一公里」——引擎如何抵达用户的项目——仍处于早期阶段：单一 curl-pipe 安装器 + GitHub raw content CDN + 三文件 VERSION 同步。

当前引擎深度绑定 Claude Code（hooks、slash commands、settings.json），其他 agent 只得到薄指针。如果要面向「任何用 AI 辅助开发的开发者」，需要结构性改造发布端。

## 决策

### D-017a · engine CLI 与 slash command 双轨共存
- `engine init` 在终端跑（agent 无关入口），`/engine-init` 在 agent 里跑（交互式）
- 两者共用 `engine/prompts/init.md` 作为 prompt 唯一真相源
- `.claude/commands/engine-init.md` 变成薄壳引用，其他 slash command 同理
- **Why**: CLI 解决跨 agent 可及性，slash command 保留 agent 在场的体验优势，prompt 不分叉
- **Alt rejected**: CLI 取代 slash command（失去交互体验）；只补 CLI 作为 fallback（维护两套 prompt）

### D-017b · 快速安装生成空模板骨架
- install.sh 铺工具文件同时生成 engine/ 最小骨架：ENGINE_MAP.md（空索引）、CONTEXT.md（空状态面板）、HANDOFF.md（空交接）、VERSION
- agent 读到 AGENTS.md 后发现空模板，自然引导用户跑 `engine init`
- 深度初始化（采访 + SYSTEM/ARCH/PITFALLS 生成）是可选第二步
- **Why**: 2 分钟内看到价值，安装后不需要跑采访就能开始

### D-017c · 每个 agent adapter 在该 agent 原生能力范围内做到最优
- 不为所有 agent 做 Claude Code 降级翻译
- 每个 adapter 的指令文件是为该 agent 撰写的完整指南：上下文加载策略 + engine CLI 用法 + agent 特有注意事项
- Claude Code 有 stop hook 硬门禁（C 层），其他 agent 安全网靠 git pre-commit（B 层）——平台能力限制，不是 adapter 质量差异
- **Why**: 「一等公民」不等于「功能等价」，而是「在该平台上做到最好」

### D-017d · plugin/ 分步迁移，不做 big bang
- Step 1: prompt 模板抽离（.claude/commands/*.md prompt → shared/prompts/）
- Step 2: agents/ 目录与现有 .claude/ 并存
- Step 3: 共享文件迁移到 shared/
- Step 4: 整体切换
- 每步保持 installer 可用
- **Why**: 单次改动量大、PR 难 review；分步迁移影响面可控

### D-017e · npm 完整 CLI 包
- engine-system 作为正式 npm 包发布
- `npx engine-system init/status/update` 直接可用，不需要 PATH 配置
- npm 既是分发渠道也是运行入口
- 「just files」哲学演化为「just one package」——安装后落地的仍是纯文件
- **Why**: npm 是最大 AI 开发者人群的工具链入口，PATH 配置是常见摩擦点
- **Alt rejected**: 纯下载器（每次跑都重新下载）；混合委托（增加复杂度但收益有限）

## 不做的事
- 不做付费/商业化（保持开源）
- 不做后台遥测/分析（隐私优先）
- 不做 Docker 镜像（引擎是文件层，不是运行时）
- 不强制任何用户切换到 npm（curl-pipe 安装继续支持）

## 实施路线
- Phase 0: 管道加固（Release 自动化 / 版本锁定 / 完整性校验 / 离线包）
- Phase 1: 通用化核心（prompt 抽离 / CLI 扩展 / 快速安装 / agent 检测）
- Phase 2: 多渠道 + 低摩擦（npm 包 / brew+scoop / 文档站）
- Phase 3: 跨 Agent 深度适配（plugin/ 迁移 / 各 agent adapter / 项目模板）
