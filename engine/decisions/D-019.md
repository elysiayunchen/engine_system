## 背景

架构师方向(2026-07-06 拍板):引擎不止当项目记忆,要升级为「agent 行为引擎」——像
Superpowers(行为技能框架,单源分发 8 个 harness)和编排类工具(Claude Code 原生
Agent Teams 等)那样,**节约 token + 统筹 agent 行为**。

勘察结论(塑造本决策的三个实况):

1. **引擎既有三件套是两类对标物都没有的底座**:契约单源编译(S3)/ 三层硬门禁(S0-S1)/
   行为证据(S4)。Superpowers 靠 prompt 自觉无硬约束,编排类工具无项目记忆。缺口只是
   两个新「面」:技能面(该怎么做)与编排面(谁去做、带多少上下文)——它们都是编译器的
   新输出靶,不是新子系统。
2. **token 浪费不在常驻注入**(已被 N1 ≤400 行机器管住),而在三处:每会话重复解释
   方法论、行为不可复现;探索性阅读把主上下文当垃圾场;HANDOFF 只增不裁的慢性通胀。
3. **2026-07-05 全面评估四发现**(验收剧场 / 防护覆盖倒挂 / 记忆膨胀 / 从未外部试点)
   此前只存在于会话记忆,本决策将其收编:a 项承载发现 1/2 的前置整改,e 项治理发现 3,
   试点安排接住发现 4(Q2)。

架构师三项拍板:独立 D-019 分期落地(不并入 D-018,不阻塞 Phase 1);编排深度 =
技能层 + 任务胶囊(不直驱进程);顺位 = 先补防护再扩面。

## 决策

### D-019a · 防护前置批(P0,其余各项的地基)
- 全部编译 dist 纳入漂移检测(现缺 dist/runtime-law.md 等,check.sh/Doctor 覆盖到全量 dist)
- `contract/src/**` 与 `dist/runtime-law.md` 加入 rules.json protected_paths
- T-017 完整性校验去空转:release 流程真实回填 manifest sha256,verify AC 从 grep
  存在性升级为哈希比对强断言
- engine-verify sh/ps1 孪生语义分叉治理(sh 用 eval / ps1 用 cmd /c),至少补 ps1 测试夹具
- **Why**: 技能面会新增一组分发到用户项目的编译产物;先把无防护面修平,新产物才不落在
  裸奔面上(评估发现 1/2 的整改)
- **Alt rejected**: 与技能化同批(单批改动面过大);后置(放大裸奔面,架构师已否)

### D-019b · 行为技能面(P1)
- `contract/src/behaviors/*.md` 新增为契约模块,纳入 budget.json 减法规则——
  **净零增长:技能正文来自既有散文迁移**(会话协议细则、命令 prompt 中的过程性指导),
  不新写平行规则
- compile 新增 behaviors dist 组:`plugin/.claude/skills/engine-<name>/SKILL.md`
  (Claude Code 原生按需加载)+ `engine/prompts/behaviors/<name>.md`(agent 中立正本,
  分发模式与 D-018a init.md 同构),manifest/install 沿既有机制分发
- 首批 5 个粗粒度技能(上限个位数,防索引膨胀):task-run(领卡→读域→动工→回写全流程)/
  scout(并行子代理侦察,只回摘要不回 dump)/ verify-writeback(验收+回写+capsule)/
  decision-draft(D-NNN 起草)/ handoff(交接收尾)
- **技能条款红线**:每条「必须」须有对应机器查点(hook/Doctor/verify),或显式标注
  「无查点,靠自觉」——防止验收剧场搬进技能层
- **Why**: 引擎目前管「不能做什么/记住什么/做没做成」,「该怎么做」空白导致行为不可复现、
  每会话重复教方法论
- **Alt rejected**: 细粒度技能库(索引自身吃 token);把方法论写长进常驻协议(违背 N1)

### D-019c · 行为路由表(P1,与 b 同批)
- 新增 `engine/domains/routing.json`(机读):触发条件(任务类型/事件)→ 技能 → 完成查点;
  SessionStart 注入路由摘要(≤10 行,计入 N1 预算);Stop hook/Doctor 消费查点字段
- **Why**: 「规则在数据表,不在散文」(Prime Directive 2)应用到行为对象;「统筹」=
  引擎按表路由,而非用户手动调 command
- **Alt rejected**: 散文路由(靠背诵);技能各自带触发描述、无中央表(机器不可消费)

### D-019d · 任务胶囊(P2)
- engine CLI 新增 `capsule T-NNN` 子命令(bin 孪生 sh/ps1):打包 L0 + 任务卡 +
  所属域 L2(CONTEXT/PITFALLS)+ 路由命中技能 → 单文件上下文包;默认打印,`--out` 可选
  落盘(generated-cache 类,不登记权威文件)
- 「上下文 = f(任务)」(Prime Directive 5)从口号变成可执行物:子代理/其他终端的 agent
  直接消费胶囊,探索垃圾不进主会话
- **进程管理不自建**:Claude Code 用原生 Agent/Teams 机制,其他 harness 由用户自行喂
  胶囊——引擎保持「文件层」定位(D-017 哲学)
- **Alt rejected**: engine 直驱 headless agent 队列 + worktree 合并管线(绑 harness、
  维护重,架构师已否,观望)

### D-019e · token 账本(P2,可与 d 并行)
- Doctor/check.sh 新增 token ledger 段:SessionStart 注入行数(扩展既有 N1 计数器)+
  技能索引大小 + 胶囊平均大小 + HANDOFF 行数
- HANDOFF 裁剪策略:会话历史保留最近 N 行(默认 10),溢出行删除——细节已由同日
  change capsule 承载,不丢信息(治评估发现 3「只增不裁」)
- CONTEXT 状态面板挂预算行(当前注入量 / 上限)
- **Why**: 「≤400 行」从单点口号扩成全链路可测;膨胀可见才可治

## 不做的事

- 不直驱 headless agent 队列 / 不自建进程管理(方案 C,观望)
- 不做细粒度技能库(首批 5 个,上限个位数)
- 不动 D-018 / Phase 1 的范围与节奏(T-020/T-021 照走,两决策无耦合)
- 技能不引入无机器查点且未标注的「必须」条款(防验收剧场搬家)
- 不为技能新写平行规则正文(净零:从既有散文迁移)
