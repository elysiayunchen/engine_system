# D-022: Doctor 补字节上限 + 单行宽度上限检查

| Field | Value |
|-------|-------|
| status | approved |
| scope | engine/scripts/engine-doctor.{sh,ps1} |
| expiry | never |
| decided | 2026-07-14 |

## Context

诺识(study_engine)项目 CONTEXT.md 膨胀到 317KB / 145 行,状态面板表格单元格被空格填充到 19600 字符/行,分隔线 57735 字符。Doctor 现有 budget_cap 只检查行数(260 行),145 行未超限,故报 0 failure —— 静默膨胀未被检测。

## Decision

在现有行数检查(budget_cap)旁,加两个检查:

1. **字节上限**:byte_cap = 行数 cap × 200(正常 markdown 每行 50-100 字符,200 给足余量)。CONTEXT.md 260 行 → 52KB,诺识 317KB 会被抓。
2. **单行宽度上限**:500 字符(正常 markdown 行很少超过 200 字符,500 给足余量,能抓 19600/57735 的膨胀)。

两个检查都报 WARN(不是 FAIL),与现有行数超限行为一致。

## Rejected alternatives

- **FAIL 而非 WARN**:膨胀是健康问题不是结构错误,且现有行数超限也是 WARN,保持一致。
- **单独的字节 cap 函数**:不需要,直接用行数 cap × 200 算出,避免维护两套 cap 表。
- **表格列数一致性检查**:太具体,行宽检查已能覆盖表格填充膨胀。
