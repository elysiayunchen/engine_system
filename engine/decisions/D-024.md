# D-024: Installer 下载失败聚合 + --local 模式 SHA256 校验

| Field | Value |
|-------|-------|
| status | approved |
| scope | install.sh, install.ps1 |
| expiry | never |
| decided | 2026-07-14 |

## Context

2026-07-14 发布端评估发现两个安装缺陷:

1. **网络模式假成功**:默认(main 分支)安装模式逐文件 `download`(curl/Invoke-WebRequest),但单文件下载失败时管道整体 exit 仍可能为 0——实测 curl schannel 握手失败后安装器继续跑完并打印成功提示,装出残缺环境而不报错。`set -euo pipefail` 只保护部分路径:`download()` 内 curl 失败会触发 ERR trap,但 runtime-law.md 段(L387)等处 `|| true` 吞掉失败;且失败无聚合计数,用户看不到装漏了几个文件。
2. **--local 跳过校验**:`verify_checksums` 只在 `--version` 网络路径生效(install.sh L391 条件 `[[ -n "$VERSION_TAG" ]] && [[ -z "$LOCAL_DIR" ]]`)。而 --local 是唯一离线可靠的安装方式,plugin/manifest.json 就在本地包里,没有理由跳过。T-017/T-022 修好的 manifest 55 条真哈希对 --local 用户完全不设防。

## Decision

1. **失败聚合硬中断**:安装循环内每个文件下载/复制后已有 `[[ -s "$dest" ]]` 空文件检查会 exit 1——保留;补上 runtime-law.md 段的失败检查(下载后验证非空,失败则 FAIL 退出而非静默);网络模式安装结束前若有任何 FAIL 不得打印 "Done/installed" 成功横幅。
2. **--local 启用 manifest 校验**:--local 模式安装完成后,用 `$LOCAL_DIR/manifest.json` 跑 `verify_checksums`,mismatch 硬失败 exit 1。skeleton 三条(dest 为 engine/{ENGINE_MAP,CONTEXT,HANDOFF}.md、fresh 后为空模板)与 .claude/settings.json(安装器改写)按现有跳过规则处理。
3. **sh/ps1 双实现同步**,行为一致;不新增安装器分支逻辑,复用现有 verify_checksums / Verify-Checksums。

## Rejected alternatives

- **--local 也走 .manifest-check.json 临时文件**:多余,LOCAL_DIR 里 manifest.json 直接可用。
- **网络模式改为先下载全部再统一校验**:改动面大,现有逐文件 `[[ -s ]]` + ERR trap 已覆盖大部分,只需堵 `|| true` 漏点。
