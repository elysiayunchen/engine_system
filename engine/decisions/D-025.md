## Context

调查确认三个可复现根因：

1. Stop hook 把 `engine/*` 全部排除在任务卡 WRITE-SET/FORBIDDEN 校验之外；现有测试还把 `engine-only -> pass` 固化为正确行为。因此模型在长会话中忘掉约束后，可直接改任意引擎文件，直到 pre-commit 才可能被少量 protected path 规则拦截。
2. 真实任务卡 T-025~T-028 使用 `## WRITE-SET` + bullet list，hook 只解析单行 `WRITE-SET:`。这 4 张卡的机器写集实际为空，门禁静默跳过。
3. Stop hook 消费整个共享工作区的 `git status`，没有 session/agent 归属。并行时一个 agent 的代码改动可被另一个 agent 的 CONTEXT/HANDOFF 改动“代打卡”；规则又要求每个 agent 都写相同共享文件，冲突是必然结果。

## Decision

1. **全部路径受任务范围约束**：WRITE-SET/FORBIDDEN 同时覆盖代码、文档与引擎文件；仅 `engine/.cache/**`、`.engine/**` 这类运行缓存豁免。解析器同时支持单行和 section-list 两种现存任务卡格式，格式不可读时 fail-closed。
2. **写前校验 + 低 token 周期重锚**：Claude Code 的 PreToolUse 在每次 Write/Edit 前检查目标路径；UserPromptSubmit 只注入不超过 5 行的任务指针（ID、GOAL、卡路径、并行归属），不重复 L0 或完整 WRITE-SET。SessionStart 才装配完整上下文；Stop/pre-commit 做收尾兜底。
3. **session 归属**：Claude hook 用 `session_id + agent_id` 记录本 agent 声明写入的路径，Stop 优先检查该清单；无法识别的 Bash/外部写入回退到保守全局检查。其他 agent 由 pre-commit 的 staged diff 兜底。
4. **并行记忆分片**：worker 不直接写共享 `ENGINE_MAP.md`、`SYSTEM.md`、`PITFALLS.md`、`CONTEXT.md`、`HANDOFF.md`、anchors、plan/spec；每个 worker 写 `engine/workstreams/<task-id>/<agent-id>/` 下自己的 `CONTEXT.md`、`HANDOFF.md` 与 evidence 引用。协调者在 merge point 重读分片后一次性更新共享记忆。
5. **共享写者机器化**：有 `agent_id` 的子 agent 直接修改共享引擎文件时，PreToolUse 硬拦；其分片路径必须包含自己的 agent ID。主 agent/无原生 hook 的环境仍须通过任务 WRITE-SET 与 pre-commit。
6. **保持文件层定位**：不自建 agent 进程队列，不接管代码分支合并。需要代码级物理隔离时由宿主使用 git worktree；本决策只解决引擎记忆与任务上下文的冲突面。
7. **一卡一目标，不一卡一消息**：任务卡对应可独立验收、通常为 commit/PR 大小的目标；同一目标的多轮消息、AC 和并行 worker 共用卡，worker 用 workstream 分片；只读调查免卡。done 卡不注入 session context，Doctor 对成功历史聚合计数，仅逐项报告失败。

## Rejected alternatives

- **只在 AGENTS.md 加粗 single-writer**：现有规则已经这样写，实测仍会抢写，无法对抗上下文遗忘。
- **给 CONTEXT/HANDOFF 加普通文件锁**：任何 agent 都能在另一 agent 持锁时直接编辑，且语义合并仍会覆盖；锁只能保护统一写入命令，不能保护任意编辑器。
- **每个 agent 都在共享 HANDOFF 追加一行**：追加仍是共享 inode，git merge 和同工作区写入都会冲突。
- **只靠 git worktree**：能隔离物理文件，但最终合并共享记忆仍冲突；必须与任务分片/单点汇总配合。
