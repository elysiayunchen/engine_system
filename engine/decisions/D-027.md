> approved: 2026-07-19 用户反馈指出常驻面板慢性膨胀——HANDOFF.md 会话历史表只进不出,52 条历史每次会话加载。要求把裁剪做成机制改动发版,而不是手动一次性裁数据。

## Decision

1. HANDOFF.md「会话历史」表保留最近 8 条;新条目追加到顶部,超出 8 条时把最旧的迁移到归档文件。
2. 归档文件命名 `engine/handoff-archive-YYYY-MM.md`(按月切分,可与多个历史月份对应);归档文件不进 SessionStart 注入,只供按需搜索考古。
3. Doctor 在 HANDOFF 历史表条目数 > 8 时输出 WARN(不硬失败,因为可能正当中断处理中)。
4. CONTEXT.md「待验证」段已 ✅ 验证的条目必须删除——段意要求"待验证",已验证项留着违背本意并造成噪音。本次顺便清理当前仓的 8 条 ✅ 划线行。
5. migrator 的 doctor_tmp managed block 加一行规则,让旧项目升级时也获得"HANDOFF 历史 ≤ 8 条,超出归档"的契约口径。
6. behaviors/handoff.md skill step 4 加归档触发:追加新行后若历史表 > 8 条,把最旧的迁移到 handoff-archive-YYYY-MM.md。
7. 版本 6.5.0 → 6.6.0(minor,新增机制);release 走 main CI 全绿 → tag → Release workflow 标准门。

## Consequences

- 每次 SessionStart 注入的 HANDOFF 内容从约 50+ 行历史压到 ≤8 行,净减几百 token;归档文件按需搜索不损失考古能力。
- 已发布项目下次 `engine update` + `engine migrate` 后获得机制,但不会自动裁剪历史——裁剪由 agent 在下次写 HANDOFF 时触发,避免 migrator 误删项目记忆。
- Doctor 新增 WARN 可能在首次升级后立即触发(老项目历史 > 8 条),这是预期信号,提示 agent 执行首次归档。
