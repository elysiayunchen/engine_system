# D-032: P037 legacy fallback 设计改造

> status: approved | scope: engine/scripts/githooks/pre-commit, plugin/engine/scripts/githooks/pre-commit, engine/decisions/D-032.md, engine/tasks/T-044.md, engine/tasks/T-044.spec.md, engine/tasks/T-044/progress.md, engine/archive/tasks/T-044-progress.md, tests/workstream/test_precommit_no_legacy_fallback.sh, tests/task-card/run-task-tests.sh, engine/CONTEXT.md, engine/HANDOFF.md, engine/handoff-archive-2026-07.md, engine/ENGINE_MAP.md, engine/changes/CHANGE-2026-07-23-03.md, engine/evidence/T-044/**, engine/domains/engine-runtime/INVENTORY.md, VERSION, engine/VERSION, plugin/VERSION, CHANGELOG.md, plugin/manifest.json | expiry: 2026-11-30(与 D-029 同期 3 个月调研窗口) | supersedes: none | related: T-044, issue #10, P037
> proposed: 2026-07-23 GitHub issue #10 报告 pre-commit L89-94 legacy fallback 在无 active 卡 + strict_task_mode=0(< 6.5)时拿 lex-largest done 卡管当前 commit,导致历史 done 卡误管新 commit(P037)。与 P038(parser bug)叠加才暴露,但 P037 是独立设计缺陷。
> approved 2026-07-23: architect 批准 Option A(移除 fallback + fail-open)。理由:done 卡不应 govern 新 commit,fallback 是 v6.5 前过渡设计,v6.5+ 已用 strict 模式替代;最小改动(删 L89-94),语义清晰。T-044 可转 active(等 T-043 done 后实施)。

## Decision

1. **移除 L89-94 legacy fallback**:无 active 卡 + 无 closing 卡时,strict_task_mode=0(< 6.5)项目**放行**(fail-open),不再拿 lex-largest done 卡当 governing 卡。strict_task_mode=1(>= 6.5)项目保持现有 L96-109 行为(无 active 卡则 block,要求显式建卡)。

2. **语义对齐**:done 卡是冷历史,不应 govern 新 commit。fallback 拿历史 done 卡是 v6.5 之前的设计,v6.5+ 已用 strict 模式替代。旧项目(< 6.5)保留 fail-open 行为(不强制 active 卡),但不再误用历史 done 卡。

3. **影响范围**:仅影响 contract-version < 6.5 且无 active/closing 卡的旧项目。这些项目无 active 卡时 pre-commit 从「拿历史 done 卡管(可能误拦)」变为「放行」。

## Consequences

- **旧项目(< 6.5)恢复可用**:无 active 卡时不再被历史 done 卡误拦(reporter 的 T-035 场景修复后不再触发)。
- **失去 fallback 安全网**:旧项目无 active 卡时 pre-commit 不再有任何 task-card 校验(纯 fail-open)。缓解:文档提示旧项目升级到 6.5+ 获得 strict 模式保护。
- **与 P038 正交**:P038(parse_task_patterns 支持 YAML frontmatter)无论本决策如何都需修(active 卡也可能用 YAML frontmatter)。

## Options Considered

- **A. 移除 fallback + fail-open(本决策选定)**——done 卡不应 govern 新 commit;旧项目 fail-open 符合 v6.5 前语义;最小改动(删 L89-94)。
- B. 移除 fallback + fail-block——旧项目也强制 active 卡,可能 break 现有工作流(用户习惯了无 active 卡也能 commit)。
- C. 保留 fallback 但限定 scope——只对 staged 中明确是该卡 WRITE-SET 内的文件放行,其他忽略。复杂,不优雅,且仍依赖 P038 修复才能正确解析 WRITE-SET。
- D. 加 opt-in 标志(ENGINE_LEGACY_FALLBACK=1)——增加配置面,不必要;旧项目用户不会主动设。

## Rationale

P037 的本质是「done 卡不应 govern 新 commit」。L89-94 fallback 是 v6.5 之前的过渡设计,v6.5+ 已用 strict 模式(strict_task_mode=1)替代。旧项目(< 6.5)保留 fail-open 是合理妥协(不强制 active 卡),但不应拿历史 done 卡兜底——这只会制造误拦(reporter 的 T-035 场景)。移除 fallback 是最小改动(删 L89-94),语义清晰,与 v6.5+ strict 模式一致。

## Watchpoints

- 旧项目用户若依赖 fallback 行为(罕见),升级后会失去兜底。需在 CHANGELOG 显著标注行为变化。
- P038 必须同步修(T-043),否则即使移除 fallback,active 卡用 YAML frontmatter 仍会炸。
- 移除 fallback 后,旧项目无 active 卡时 pre-commit 完全跳过 task-card 校验(仅保留 protected_paths / worker mode / memory-written 检查)。
