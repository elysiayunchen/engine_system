## Decision

1. **批准 T-043 P038 修复的完整 WRITE-SET 范围**,包括 protected_paths 中的 `plugin/manifest.json`(因 pre-commit SHA256 变更必须同步)。

2. **语义说明**:T-043 是 pre-commit parser bug fix,改 pre-commit → manifest SHA256 变 → manifest 必须同 commit 提交。manifest 更新是 T-043 的固有副作用,非跨任务越界。protected_paths 门禁目的是防跨任务卡改动,不阻止任务卡改自己触发的 manifest 哈希。

3. **与 D-032 正交**:D-032 批准 T-044(P037 legacy fallback 移除),D-033 批准 T-043(P038 parser fix)。两者改同一文件(pre-commit)但解决不同问题(P038 parser vs P037 fallback),分两张任务卡 + 两个决策。

## Consequences

- T-043 commit 可通过 protected_paths 门禁(manifest 由 D-033 scope 覆盖)。
- 不改变 protected_paths 设计:plugin/manifest.json 仍 protected(防非任务卡 commit 随意改哈希)。
- 不扩展 T-041 自身豁免范围到 manifest(manifest 不是任务卡衍生文件,是全局完整性文件)。

## Rationale

T-043 原标 `decision: none` 在 check.sh(engine verify)阶段不触发问题(check.sh 不查 decision scope),但在 `git commit` 阶段触发 pre-commit protected_paths 门禁。这是 D-030 已确立的先例:任何改 pre-commit 的任务都必然改 manifest(protected),需要决策覆盖 manifest。D-033 复用此模式。

## Watchpoints

- T-044(D-032)实施时也会改 pre-commit → manifest,D-032 scope 需扩展加 plugin/manifest.json(留 T-044 实施时处理)。
- 本决策不改变 plugin/manifest.json 的 protected 状态;未来可考虑将 manifest 哈希更新纳入 T-041 自身豁免(但 manifest 非任务卡衍生文件,语义上不应豁免)。
