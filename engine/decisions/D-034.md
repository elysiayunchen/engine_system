# D-034: contract debt_baseline 计量修正(47→54)

> status: approved | scope: contract/budget.json, engine/decisions/D-034.md, engine/CONTEXT.md, engine/HANDOFF.md, engine/handoff-archive-2026-07.md, engine/ENGINE_MAP.md, engine/changes/CHANGE-2026-07-23-07.md, engine/domains/engine-runtime/INVENTORY.md | expiry: none(计量修正,无时间窗) | supersedes: none | related: T-040, D-028
> proposed 2026-07-23: T-040(dbffd66 v6.11.3)设 debt_baseline=47 时计量错误——当时实际 debt 已 ≥53(MUST=66, Rules=13, debt=53)。v6.11.4 commit 0303c29(ceremony scaling guidance)新增 1 个 MUST,debt 涨至 54。Doctor 一直 WARN(54>47)但非阻塞,CI 仍绿。根因是 T-040 设 baseline 时未跑 doctor 实测 debt,凭预估设了 47。
> approved 2026-07-23: architect 批准 Option A(修正 baseline 到真实值 54)。理由:debt 增长非 v6.11.4~v6.11.8 新引入债务(该期间 contract/src/ 仅 0303c29 一个 commit,新增 1 MUST),而是 T-040 历史计量设错。提升 baseline 到真实值 54 比人为压低散文 MUST 强度更合理(这些 MUST 是 ENGINE_MAP 模板/Re-anchor/Read-gate 等核心强制条款,不应弱化)。

## Decision

1. **修正 debt_baseline 47→54**,反映 contract/src/ 当前的真实 MUST 计数(MUST=67, gated Rules=13, debt=54)。

2. **根因说明**:T-040(dbffd66)设 baseline=47 时未跑 doctor 实测,凭预估设值。实测当时 debt 应为 53(MUST=66)。v6.11.4(0303c29)新增 1 MUST(ceremony scaling guidance),debt 涨至 54。此 7 个超 baseline 的 debt 全部是历史存量,非 v6.11.4~v6.11.8 新引入。

3. **不弱化散文 MUST**:54 个 debt 中的 MUST 是 ENGINE_MAP 模板规则、Re-anchor、Read-gate、Lifecycle Transaction 等核心强制条款,不应为满足 baseline 而弱化为 SHALL/将/需要。

## Consequences

- Doctor WARN 消除(debt=54 == baseline=54,net-zero holding)。
- contract/budget.json 的 _comment 追加 D-034 修正记录(沿用既有模式)。
- 未来新增 MUST 仍须净零增长或决策背书提升 baseline(规则不变)。

## Rationale

budget.json _comment 既有模式:每次版本升级 + 决策背书 + 理由记录(如 D-004/D-015/D-028/T-040 等)。D-034 是修正 T-040 的计量设错,不是为新增债务放水。真正的 7 个 debt 全部是 v6.11.3 之前就存在的核心条款 MUST,弱化它们会损害契约强度。修正 baseline 到真实值是最小改动 + 最合理选择。

## Watchpoints

- 此修正不改变 max_lines(2940)/max_rules(13),仅改 debt_baseline。
- 未来若新增 Hard Rule(提升 max_rules),须同步评估 debt_baseline 是否需再提(新 Rule 的 gated MUST 不计入 debt)。
- T-040 设 baseline 的教训:未来设 baseline 必须先跑 doctor 实测 debt,不能凭预估。
