## Background — 审视实证(2026-07-26)

v6.11.0(D-029/T-036)解决的是「多顶层会话抢写共享三件套」。但用户实际痛点是**多会话各干各的任务卡**,这是另一层:任务门禁全栈是单卡假设。加上锁液性实现缺陷,保护空转。

| # | 根因 | 证据 | 后果 |
|---|------|------|------|
| RC-1 | 三层门禁(PreToolUse `block_scope` / Stop / pre-commit)都取**字典序第一张 active 卡**,所有路径按这一张卡的 WRITE-SET 校验 | `engine-hook-stop.sh:67-77` `find_active_task` first-match break;pre-commit L100-103 同款 | 双 active 卡时,第二个 agent 的一切写入/提交按别人的卡判定 → 全被拦 |
| RC-2 | 任务/决策卡 bootstrap 豁免(`is_task_bootstrap_path`)只在「零 active 卡」分支生效 | `engine-hook-stop.sh:171-176`;pre-commit L114-127 | 只要有任一 active 卡,其他会话连**新建自己的任务卡**都被 PreToolUse 拦截 |
| RC-3 | `session.lock` 记录的 pid 是 **hook shell 自身**(`ms_pid="$$"`),hook 退出即死 → 每个新会话 `kill -0` 判 stale → 自封 coordinator | 实证:`engine/.cache/session.lock` pid=5112(已死),tombstone=`stale-recovered`,每次会话启动都接管 | 锁形同虚设,人人都是 coordinator,v6.11.0 共享三件套保护**实际空转** |
| RC-3b | `.role=worker` 旗标无人清理;coordinator 上位时不删自己的旧旗标 | 实证:2026-07-23 的两个 `.role=worker` 文件残留至今 | 会话 resume(同 session_id)后永远被当 worker:PreToolUse 拦共享记忆写入,Stop 又逼回写 → 死锁 |
| RC-4 | worker 分片路径钉死在第一张 active 卡(`engine/workstreams/${active_task_id}/…`);`is_shared_memory` 一揽子涵盖**所有任务**的 progress.md/checkpoint.md | `engine-hook-stop.sh:242,140-150` | 干别的卡的 worker 连自己任务的分片/进度都写不进 |
| RC-5 | pre-commit protected 检查(`engine/tasks/**` 在 protected_paths)只豁免**单一** active 卡自身(T-041 exempt_id) | pre-commit L236-249 | 第二张卡字典序靠后时,提交自己的卡被判 protected 违规(no task decision) |

结论:**D-029 的「多会话 = 多 worker 共享一张卡」模型与用户「多会话 = 各持一张卡」的真实用法错位**,且锁液性实现有缺陷。两者都修,架构不推翻。

## Decision

契约版本 **v6.12.0**。核心原则:**任务卡即租约(lease)——门禁按「路径 ∈ 哪张卡」判定,不再全局单卡;会话活性按 heartbeat 判定,不再按瞬时 pid。**

1. **Union gating(修 RC-1)**:三层门禁改为收集**全部** active 卡(+dirty done 收尾卡)。路径放行条件:∃ 卡 C,路径 ∈ C.WRITE-SET 且 ∉ C.FORBIDDEN。任何卡都不覆盖时才拦,报错列出所有 active 卡及其 WRITE-SET。某卡的 FORBIDDEN 不再挡另一张卡 WRITE-SET 内的路径(FORBIDDEN 只约束本卡范围)。Stop 域路由检查同款:用覆盖该路径的卡的 domain。
2. **Bootstrap 恒豁免(修 RC-2)**:`engine/tasks/T-*.md`、`engine/decisions/D-*.md` 的写入在 PreToolUse/Stop 层恒放行(不再限于零 active 卡分支)。建卡/激活/更新自己的卡永不被别人的卡拦截。
3. **Protected 逐卡豁免(修 RC-5)**:pre-commit protected 检查中,staged 的 `engine/tasks/T-NNN.md`(及其 .spec/子目录/归档 progress)若 **T-NNN 自身**为 active 或 staged-done,即豁免——豁免主体从「单一 exempt_id」改为「每张卡豁免自己」。决策卡 `engine/decisions/D-NNN.md` staged 时同理恒豁免(bootstrap 通道;防篡改靠 git 历史与审阅,不靠写锁)。其余 protected 路径逐文件找覆盖它的 active 卡,用**那张卡**的 decision 校验(替代单卡 task_decision)。
4. **锁液性 = heartbeat 而非 pid(修 RC-3)**:lock 内 pid 字段保留仅作诊断。活性判定改为:`session.lock` 的 mtime 或持锁会话的 `.cache/sessions/<key>.hb` mtime 在 TTL 内(默认 120 分钟,`ENGINE_SESSION_TTL_MIN` 可调)。PreToolUse 每次触发 touch 本会话 `.hb`(廉价、每次工具调用都续租);UserPromptSubmit --guard 同款续租,且持锁会话顺手 touch lock。超 TTL → stale → 新会话接管 + tombstone(既有流程)。`kill -0` 降级为辅助信号(pid 活着且未超 TTL 才算活)。
5. **Coordinator 写共享三件套时验租约(修 RC-3 的对偶面)**:PreToolUse 拦截共享单例文件时新增正向校验——lock 存在且 `lock.sid ≠ 本会话 sid` 且未 stale → 拦截(提示 `engine assume-coordinator`);lock stale → 原子接管后放行。共享三件套保护从「旗标被动标记」升级为「写时验锁」,失联 coordinator 回来乱写的窗口关闭。
6. **Role 旗标生命周期(修 RC-3b)**:会话在 SessionStart 取得/接管 coordinator 时删除自己的 `.role=worker` 旗标;Stop hook 会话收尾时删除本会话旗标;SessionStart 顺手清理 mtime 超 7 天的孤儿旗标与 `.hb`/`.meta`/`.paths`。
7. **Worker 语义收窄(修 RC-4)**:worker 拦截面从 `is_shared_memory` 一揽子收窄为**共享单例**(根三件套 + SYSTEM/REPO_GUIDE/PITFALLS/SPRINT/ROADMAP + AGENTS.md/CLAUDE.md + domains/*/{CONTEXT,PITFALLS,INVENTORY} + plans/specs)。任务局部文件(`engine/tasks/T-*/progress.md`、`engine/evidence/T-*/checkpoint.md`)回归 union WRITE-SET 治理——各卡 WRITE-SET 天然只含自己任务的文件,不同卡的顶层会话互不干扰。**同会话派生 subagent(agent_id 非空)保持旧一揽子拦截**(它们是本会话任务的帮手,走分片由 coordinator 合并,v6.5 语义不变)。worker 分片路径放宽为 `engine/workstreams/<任一 active 卡>/<sid>/`。
8. **展示层多卡化**:UserPromptSubmit guard 列出全部 active 卡(id + GOAL 截断);SessionStart 注入全部 active 卡全文(≤3 张,超出仅注 header 行);`engine context` Active Tasks 面板同步多卡。
9. **发布可移植性**:本决策影响**所有已安装项目**。plugin 镜像 byte-identical 同步;`engine-migrate-contract` 追加 v6.12.0 迁移项(AGENTS.md managed block 措辞更新:单卡措辞 → 多卡租约措辞);contract/src 多会话规则段修订,行数预算净零(改写 v6.11.0 段落,不新增规则条目,13/13 不变)。老项目(contract-version < 6.12.0)行为不变(fail-open 兼容);新项目 fail-closed 走新语义。

## Options Considered

- **A. Union gating + heartbeat 租约(本决策)**——门禁逐卡判定,活性按心跳。优点:改造面集中在既有脚本,架构不动,B 档 pre-commit 同样受益(union 不依赖 hook);缺点:多卡并存时互相写对方 WRITE-SET 交集路径仍可能竞态(见 Consequences 固有边界)。
- B. 会话-任务强绑定(`.cache/sessions/<key>.task`,PreToolUse 按本会话绑定卡单卡校验)——更精确,但 pre-commit(无会话身份)仍需 union 兜底,双语义并存复杂;绑定时机(建卡?首写?显式命令?)引入新状态机。**作为 v6.12.x 可选增强保留,不进本期**。
- C. 强制 git worktree 物理隔离——D-029 已否决(UX 摩擦),维持不采纳。
- D. 单卡串行 + 排队(第二会话等第一张卡 done)——直接违背用户「并行」诉求,否决。

## Consequences

- **强制力变化(诚实声明)**:bootstrap 恒豁免 + protected 逐卡豁免意味着任何会话可新建/修改任务卡与决策卡——防线从「写锁」移到「git 历史 + 架构师审阅 + Doctor」。这是并行能力的代价,与 v6.5「一目标一卡」原则兼容(卡是公开租约,不是私产)。
- **固有边界**:两张 active 卡的 WRITE-SET 若声明了交集路径(如都含 `engine/ENGINE_MAP.md`),union gating 放行两边,竞态回到共享单例锁(第 5 条)与 git 层。共享单例之外的交集冲突不做机器仲裁——卡作者应收窄 WRITE-SET。Doctor 新增 WARN:检测多张 active 卡 WRITE-SET 交集(共享三件套除外)。
- **TTL 权衡**:120 分钟内 coordinator 空闲不丢锁;超时后接管,原会话回来写共享单例会被写时验锁拦下并提示 assume-coordinator,无静默覆盖。长自治运行(无用户 prompt)由 PreToolUse 续租覆盖。
- **上下文预算**:SessionStart 多卡注入以 3 张全文为帽(N1 ≤400 行预算内,超出降级 header);guard 每卡 2 行。
- **契约预算**:contract/src 修订 v6.11.0 多会话段,目标净零(2940 cap 不动,规则数 13 不变);若实测超线,削同段旧散文,禁动其他规则。
- **测试面**:tests/task-card(多卡 union 用例)+ tests/workstream(跨卡分片)+ 新 tests/multi-session(液性/旗标清理/写时验锁);hook-parity sh/ps1 对偶更新。
