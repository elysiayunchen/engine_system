## Background — 问题实证(2026-07-29)

v6.5+ strict-task 模式下,pre-commit hook 在「无活跃任务卡」时全量拦截普通文件提交(L179-192)。这本是为产品代码设的纪律,但连累了非产品路径:

1. **跨 agent anchor 文件**(`engine-sync-agent-anchors` 同步的 `.github/copilot-instructions.md`、`GEMINI.md` 等)
2. **`engine update` 拉的工具维护文件**(`engine/scripts/**`、`engine/prompts/**`、`engine/bin/**`)
3. **项目级配置**(`.claude/settings.json`、`.gitignore`、`CHANGELOG.md`)

现状只能靠「建一次性任务卡」或 `--no-verify`(后者绕掉所有检查,不安全)。Issue #17 提案在 repo 根加 `.engineignore`(gitignore 语法),匹配路径旁路任务卡门禁。

## Decision

契约版本 **v6.13.0**。核心原则:**`.engineignore` 是精细化的旁路通道,不是 `--no-verify` 的替代——它只跳 WRITE-SET 归属,不跳 FORBIDDEN/protected/dist-stale。**

### D1:匹配引擎 — 复用 match_any_glob(修正 issue 提案)

Issue 提案建议用 `git check-ignore --exclude-from`,但实证 `git check-ignore` **不支持 `--exclude-from` 选项**(那是 `git ls-files` 的)。`git check-ignore` 只读 `.gitignore`/`.git/info/exclude`/`core.excludesFile`,无法指定额外的 ignore 文件。

**采用**:复用 pre-commit hook 既有的 `match_any_glob`(L83-100),用 `case "$path" in $p|$p/*)` 匹配。Shell `case` 的 `*` 跨 `/`(不像标准 glob),所以 `engine/scripts/**` 中 `**` 等同于 `*`,能匹配深层子路径。尾部 `/**` 预处理剥掉,使裸目录名也能匹配。纯 shell 零子进程,性能优于 git check-ignore(符合 L88-90 性能注释)。

### D2:`.engineignore` 自身防护 — 双保险

- **(a) 保护路径**:`.engineignore` 加入 `rules.json` protected_paths → 改它需要一张覆盖决策(留审计痕迹)
- **(b) Doctor 内容告警**:发现 `.engineignore` 含 `src/**`/`runtime/**`/`contract/**` 等产品路径时 WARN

### D3:FORBIDDEN 交互 — 跳 WRITE-SET 不跳 FORBIDDEN(修正 issue 提案漏点)

Issue 提案在 194-213 的 `union_allows` 循环里也加 `continue`,但这会绕过 FORBIDDEN——违反 issue 自己声明的"不绕过保护路径检查"精神(FORBIDDEN 是卡片级硬规则)。

**修正**:新增 `union_not_all_forbidden` 辅助函数(存在任一卡未禁即放行)。`.engineignore` 路径走它而非 `union_allows`:
- 全部卡都禁 → block(消息:"engineignored but FORBIDDEN by every governing card")
- 任一卡未禁 → pass(跳过 WRITE-SET 归属检查)

### D4:engine-init 生成注释模板

`engine/skeleton/.engineignore` 是注释掉的模板(跨 agent anchor + engine 工具路径 + 项目配置),用户取消注释即用。`engine-init` 经 skeleton 复制时带入。

### 旁路范围(明确边界)

| 门禁 | `.engineignore` 路径是否旁路 |
|------|---------------------------|
| L179-192 无卡 block | **是** |
| L194-213 union_allows WRITE-SET | **是**(改走 union_not_all_forbidden) |
| L194-213 FORBIDDEN | **否**(union_not_all_forbidden 仍查) |
| L289-343 protected-path | **否**(独立代码路径) |
| L353-387 dist-stale | **否**(独立代码路径) |

## Rationale

- **为什么不沿用 `--no-verify`**:绕掉所有检查(包括 dist-stale、protected),不安全。
- **为什么不建一次性任务卡**:ceremony for non-product work,污染任务历史。
- **为什么不用环境变量 `ENGINE_SKIP_CARD=1`**:不可发现、不版本控制、不能按路径细粒度控制。

## Non-goals

- `.engineignore` 不豁免产品路径(`runtime/**`/`src/**`/`contract/**`),写了 doctor WARN。
- `.engineignore` 不是 `.gitignore` 的替代——它不控制 git 是否跟踪文件,只控制 pre-commit 任务卡门禁是否拦。
