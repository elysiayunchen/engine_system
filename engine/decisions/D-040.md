# D-040: Review provenance 过期判定改为 ancestor-of-HEAD

status: approved
scope: engine/scripts/engine-doctor.sh, engine/scripts/engine-doctor.ps1
date: 2026-08-01
decided-by: architect

## Context

v6.20.0 (T-070) 的 `check_review_evidence` 用 `write_provenance.commit != HEAD` 判定 review evidence 过期（stale）。但 D-009 正常 Coordinator closeout 会在 review 之后提交 evidence / 任务卡 / CONTEXT / HANDOFF / ENGINE_MAP / 变更胶囊，这些提交合法推进 HEAD，导致精确相等判定在每个正常收尾流程中必然触发假的 `stale review evidence` 警告（issue #28 / T-087 复现）。review commit 仍是 HEAD 的祖先，没有任何代码被 rebase 掉或分叉。

## Decision

1. doctor 的 stale 判定从「commit 精确相等」改为「review commit 是否仍可从 HEAD 可达」：
   - `prov_commit == HEAD` → 有效（非 stale）。
   - `prov_commit != HEAD` 且 `git merge-base --is-ancestor prov_commit HEAD` 成功 → 有效（closeout 提交合法推进，非 stale）。
   - `prov_commit != HEAD` 且不是 HEAD 祖先（被 rebase 掉 / 分叉 / 未知 commit）→ 仍报 `stale review evidence` WARN。
2. bash 与 PowerShell 孪生行为对等（ps1 用 `git merge-base --is-ancestor` 退出码判定）。
3. 其余判定（writer / argv / tool_unavailable / status=block / missing evidence 分档）不变。

## Rationale

- review 的对象是「被接受的候选」；closeout 提交（非代码）在其之上推进 HEAD 是契约要求的正常流程，不应使 review 失效。
- ancestor 判定是 git-native、零配置、零新依赖的正确语义：只有真正分叉/被丢弃的 review 才算过期。
- 保持 WARN 档（非 FAIL）：即便 stale 也不阻断，仅提示架构师，符合 review gate 既有分级。

## Expiry

永久（语义性决策）。
