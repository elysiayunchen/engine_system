# D-042: 多宿主适配 — 安装命令分轨

status: proposed
scope: engine/install, engine/scripts/engine-hook-*, plugin/
date: 2026-08-01
decided-by: architect

## Context

引擎治理层（SessionStart/PreToolUse/Stop hook）当前绑死 Claude Code hook 协议（.claude/settings.json）。架构师在 QoderWork、Cursor 等非 Claude-Code 环境工作时，引擎完全不在场——治理真空。TDAI 有同样限制（after-tool-call/before-prompt-build 依赖宿主 hook 执行点）。

## Decision

采用**安装命令分轨**方案：不同 `engine install --host=<agent>` 命令生成对应宿主的适配配置。

方向要点：

1. hook 核心逻辑保持协议无关（纯 bash，输入=环境变量+stdin JSON，输出=stdout JSON）
2. 每个宿主一个 adapter 层：Claude Code → settings.json hook；QoderWork → AGENTS.md 注入 + awareness 协议；Cursor → .cursorrules 注入；通用 → pre-commit（git 层，天然跨宿主）
3. 安装命令检测/指定宿主，生成对应 adapter 配置，不修改核心脚本
4. 降级策略：宿主不支持某 hook 点时，该治理环节标记为 manual（不静默跳过）

## Trigger

多会话扩展（multi-session）需求启动时实施。当前仅注册方向，不建卡。

## Rationale

- 低成本：adapter 是薄配置层，核心脚本零改动
- 高杠杆：一次设计覆盖所有未来宿主
- pre-commit 已天然跨宿主，证明 git 层治理不依赖特定 agent
