**Verify**: `grep -A2 'sync.*VERSION\|update.*VERSION' engine/scripts/engine-migrate-contract.sh | grep -q 'printf.*VERSION\|echo.*VERSION\|cat.*VERSION'`

### AC-2: VERSION 卡死 bug 修复(.ps1 parity)
**Criterion**: `engine-migrate-contract.ps1` 同步修复,bash 与 PowerShell 行为一致。
**Verify**: `grep -qi 'Set-Content.*VERSION\|Out-File.*VERSION' engine/scripts/engine-migrate-contract.ps1`

### AC-3: Doctor 新增 check_legacy_data_format(.sh)
**Criterion**: `engine-doctor.sh` 新增 `check_legacy_data_format` 函数,检测四类格式特征:
1. 任务卡无 v6 头(无 `write-set:` 或 `status:`)
2. rules.json protected_paths 仍是默认单元素 `["runtime-law.md"]`
3. changes/ 有 capsule 但 tasks/ 空
4. evidence/ 有 .md 但无 T-NNN/AC-N.json
**Verify**: `grep -q 'check_legacy_data_format' engine/scripts/engine-doctor.sh && grep -c 'WARN.*legacy\|WARN.*老格式\|WARN.*v6' engine/scripts/engine-doctor.sh | grep -q '[4-9]'`

### AC-4: Doctor 新增 check_legacy_data_format(.ps1 parity)
**Criterion**: `engine-doctor.ps1` 同步实现,bash 与 PowerShell 行为一致。
**Verify**: `grep -qi 'check_legacy_data_format\|Check-LegacyDataFormat' engine/scripts/engine-doctor.ps1`

### AC-5: 空项目不误报
**Criterion**: 在空项目(无 changes/ 无 tasks/ 无 evidence/)上跑 Doctor,`check_legacy_data_format` 不报 WARN(因为无数据无残留)。
**Verify**: `tmpdir=$(mktemp -d) && mkdir -p "$tmpdir/engine/tasks" "$tmpdir/engine/decisions" "$tmpdir/engine/changes" "$tmpdir/engine/evidence" && printf '{"rules":[],"protected_paths":["runtime-law.md"]}' > "$tmpdir/engine/decisions/rules.json" && (cd "$tmpdir" && bash /e/projects/engine_system/engine/scripts/engine-doctor.sh 2>&1 | grep -c 'legacy\|老格式') ; rm -rf "$tmpdir"`

### AC-6: 老项目正确报告
**Criterion**: 在有 changes/ 但无 tasks/ 的 fixture 上跑 Doctor,输出含 "changes" 和 "0" 的 WARN。
**Verify**: `tmpdir=$(mktemp -d) && mkdir -p "$tmpdir/engine/tasks" "$tmpdir/engine/decisions" "$tmpdir/engine/changes" "$tmpdir/engine/evidence" && printf '{"rules":[],"protected_paths":["runtime-law.md"]}' > "$tmpdir/engine/decisions/rules.json" && for i in 1 2 3; do echo "# CHANGE-2026-01-0$i" > "$tmpdir/engine/changes/CHANGE-2026-01-0$i.md"; done && (cd "$tmpdir" && bash /e/projects/engine_system/engine/scripts/engine-doctor.sh 2>&1 | grep -E 'changes.*0.*任务卡|changes.*0.*task') ; rm -rf "$tmpdir"`

## CONSTRAINTS

1. **不引入新概念**:不引入 schema_version / migration chain / 考古层化等任何新抽象
2. **不动契约**:不改 contract/src/、不调 budget.json、不加新 MUST 规则
3. **不动分发链**:不改 plugin/manifest.json、不改 install.sh
4. **对新用户零冗余**:空项目跑 Doctor 不误报,跑 migrator 看到简洁提示
5. **版本无关**:check 检测"格式特征"而非"版本号",未来 v7 改格式时只需更新 check 特征
6. **不自动转换**:check 只报告不修复——老数据保持原样(git history 是考古层)
7. **双实现 parity**:.sh 与 .ps1 行为一致
8. **不破坏 migrator idempotent**:修复 VERSION bug 后,migrator 仍可重复跑(值相同则无副作用)

## NOTES

### 为什么是 MVP 而非大方案

本任务卡经历了三次方案迭代(Option C → Option D → 三层可持续方案),均被子代理审视否决。最终共识:核心问题只需修复 1 个 bug + 加 5-10 行 Doctor check,不需要新框架。详见 D-021 的"已否决方案"记录。

### 可持续性说明

本方案不能"一劳永逸",但设计为可持续:
- 检测逻辑是"格式特征"而非"版本号"——任何老格式都会被检测
- 每次迭代的成本是"改 5 行代码"——未来 v7 发版时,开发者只需更新 Doctor check 的格式特征
- 复用现有机制(run_migrate 调度器 + reconcile_schema + Doctor run_custom_checks)
- git history 承担考古层,不重复造轮子

### 不做的事

- 不生成 stub 任务卡/决策/AC JSON(语义错位)
- 不引入 schema_version 字段(冗余于 engine/VERSION)
- 不写 migration step(调度器已存在,但当前不需要)
- 不做考古层化标记(git history 已承担)
