## 设计要点(实施时参考)

### INVENTORY.md 总览模板(≤120 行)
```markdown
| Feature | Entry file | Public API | Status | Last verified |
|---------|-----------|------------|--------|---------------|
| 任务卡解析 | engine/tasks/README.md | parse_task_card(id) | stable | 2026-07-19 |
```

### 分级规则
- **总览** `engine/domains/<domain>/INVENTORY.md`:≤120 行,5 列表格,只列功能 + 入口文件路径 + API 契约名(不展开签名)
- **子文件** `engine/domains/<domain>/INVENTORY/<feature>.md`:agent 接管时按需 Read 单个,含 API 签名 + 调用关系摘要 + 配置项
- **不进 SessionStart 全文注入**,只首行摘要(`engine/domains/<domain>/INVENTORY.md` 第 1 行)进域仪表盘

### 与现成工具的边界(关键)
| 内容 | 写在哪 | 谁生成 |
|------|--------|--------|
| Feature 名(语义层) | INVENTORY 总览 | 人写(agent 在 done 时) |
| Entry file 路径 | INVENTORY 总览 | 人写 |
| Public API 契约名 | INVENTORY 总览 | 人写 |
| API 完整签名 | INVENTORY 子文件 | 人写 + ast-grep 校验 |
| 符号定位(谁定义在哪) | 不写,现生 | ast-grep / ctags |
| 调用链 | 不写,现生 | ast-grep / grep |
| 数据流 | 不写,现生 | grep + agent 临时分析 |

### 双向 FAIL 检查
- **code→INVENTORY**:已 done 任务涉及的文件路径必须在某条 INVENTORY 行的 Entry file 中出现(或其所在域的 INVENTORY 至少有一条对应行)
- **INVENTORY→code**:每行 Entry file 路径必须存在(`test -f`)
- **FAIL 级**(非 WARN):任一方向失败 = doctor exit 非 0
- **迁移宽限期**(D-028 §9):contract-version < 6.8.0 时,双向 FAIL 降级为 WARN;函数读 `ENGINE_DOCTOR.md` 首行 `<!-- contract-version: X -->` 标记判定(与 `check_legacy_data_format()` 范式对齐)
- **migrator stub**(D-028 §9):migrator 在升级时写入空表头 stub 到 `engine/domains/<domain>/INVENTORY.md`(由 `engine-migrate-contract.sh` / `.ps1` 落实,与 contract-version 头同款 upsert_block 机制)
- **机制 C — API 唯一性**(D-028 §10 机制 C,挂 AC-6.1):Doctor 扫描所有域 INVENTORY.md + 子文件的「Public API」列,全仓唯一,重复 = FAIL;迁移宽限期同 §9(< 6.8.0 时 WARN)

### 维护时机
