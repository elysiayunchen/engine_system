## 设计要点(实施时参考)

### linter 委托优先级
| 文件类型 | 首选 linter | fallback |
|---------|------------|---------|
| .sh | shellcheck | 自研 grep `^function\s+\w+` + 全仓 grep 调用 |
| .ps1 | PSScriptAnalyzer (Invoke-ScriptAnalyzer) | 自研 grep `function\s+\w+` + 全仓 grep 调用 |
| .md / .json | 跳过(无函数概念) | — |
| 其他 typed 语言(.ts/.py/.go 等) | tsc --noUnusedLocals / vulture / go vet 等 | 自研 grep |

### 反向调用点扫描
1. 解析 WRITE-SET,git diff 取本任务新增/修改/删除的标识符(函数名、类名、变量名)
2. 对每个标识符,全仓 grep 是否有调用点(排除定义本身、注释、字符串字面量)
3. 无调用点 → 加入 DEAD-CODE.json

### DEAD-CODE.json 格式
```json
{
  "task_id": "T-NNN",
  "checked_at": "2026-07-19T12:00:00Z",
  "exempt_all": false,
  "exempt_reason": null,
  "dead_code": [
    {
      "symbol": "function_name",
      "file": "engine/scripts/foo.sh",
      "line": 42,
      "linter": "shellcheck",
      "exempt": false,
      "exempt_reason": null
    }
  ],
  "exempt_count": 0,
  "fail_count": 0
}
```

顶层 `exempt_all: true` + `exempt_reason: "<理由>"` = 批量豁免全部 entry(D-028 §9),`check_warn_done_gate` 优先读顶层,不需逐条标。per-entry `exempt: true` 是细粒度选项,可与顶层独立使用。

### COPY-PASTE.json 格式(jscpd 委托输出,D-028 §10 机制 B)
```json
{
  "task_id": "T-NNN",
  "checked_at": "2026-07-19T12:00:00Z",
  "tool": "jscpd",
  "jscpd_available": true,
  "duplications": [
    {
      "format": "sh",
      "lines": 50,
      "tokens": 300,
      "firstFile": { "name": "engine/scripts/foo.sh", "start": 10, "end": 60 },
      "secondFile": { "name": "engine/scripts/bar.sh", "start": 5, "end": 55 },
      "fragment": "...",
      "exempt": false,
      "exempt_reason": null
    }
  ],
  "warn_count": 0
}
```

`jscpd_available: false` 表示 jscpd 不可用,verify 降级到 skip + WARN(不计具体重复条目)。token 阈值与最小块长用 jscpd 默认。

### WARN 升级为 done 门项
- verify 完成:`fail_count=0 && warn_count=0` → 自动通过
- `fail_count=0 && warn_count>0` → 须架构师在 DEAD-CODE.json 中标 `"exempt": true, "exempt_reason": "<理由>"`,或顶层 `"exempt_all": true, "exempt_reason": "<理由>"`(D-028 §9 批量豁免)
- Doctor 检查 evidence/T-NNN/DEAD-CODE.json:warn_count>0 且未全部豁免 → FAIL
- **迁移宽限期(D-028 §9)**:`check_warn_done_gate` 读 `ENGINE_DOCTOR.md` 首行 `<!-- contract-version: X -->` 标记,`contract-version < 6.10.0` 时降级为 WARN(不阻塞 done),与 `check_legacy_data_format()` 范式对齐

### 豁免场景(合理 WARN)
- 库项目导出未使用 API
- 测试 fixture 辅助函数
- 动态调用(eval / & $cmd / 反射)— linter 抓不到,自研 grep 也抓不到,只能人工标注

### 显式不做
- 不自研 AST 解析器
- 不覆盖软死代码(冗余复刻)— 靠 T-033 INVENTORY 兜底,agent 接管时读 INVENTORY 知道已有功能
- 不引入跨语言别名表(镜像对死代码靠 linter 自身识别)
- 不硬失败所有 WARN(只让 warn_count>0 时 done 须豁免)
