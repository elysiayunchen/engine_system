# T-036.spec: 多会话锁 + worker 自动降级 + PreToolUse 双信号 + v6.11.0 发布

> status: active | decision: D-029 | twin of: T-036.md | contract-version-target: 6.11.0

## Spec 概述

T-036 落地 D-029 approved 决策:把"多 Claude Code 实例并行抢写引擎记忆三件套(CONTEXT.md / HANDOFF.md / ENGINE_MAP.md)"做成机制。4 路子代理审视后修订主线方案:多会话 lock file + 第二个会话自动降级为 worker 模式 + PreToolUse 双信号扩展。

## 关键事实(4 路审视揭示)

1. **session_id 不需要重新生成**——Claude Code 已通过 hook payload 传入 `session_id`(Stop hook 在 `engine-hook-stop.sh:191-197` 已在用),SessionStart hook 完全未使用。本任务只需扩展 SessionStart hook 复用 Claude Code 提供的 session_id
2. **归属账本已是每会话本地**——`.cache/sessions/<session_key>.paths` 文件名已用 session_id 隔离,零抢写。只需新增 `.meta` 文件(单行,角色 + 时间戳)
3. **PreToolUse 拦截信号必须扩展**——现有 `[ -n "$agent_id" ]` 单信号对多顶层会话失效(顶层会话的 agent_id 为空)。必须扩展为双信号:`[ -n "$agent_id" ] || [ -n "$ENGINE_SESSION_ROLE" -a "$ENGINE_SESSION_ROLE" = "worker" ]`
4. **atomic 独占 lock**——POSIX 用 `noclobber`(无外部依赖),Windows 用 `FileStream(FileShare.None)`(OS 保证无 TOCTOU)
5. **pid+StartTime 双信号比对**——防 pid 复用;Windows `Get-Process.StartTime` 精度到秒容差 2 秒;Linux `/proc/<pid>/stat` 第 22 字段 starttime
6. **AGENT_ADAPTERS.md 不新增 D 档,作为 C 档扩展子段**——多会话锁是 hook 触发机制扩展,不是新能力档位

## fail-open vs fail-closed 边界

- 老项目(contract-version < 6.11.0):SessionStart 检测到 lock 存在时仅 WARN 不强制 worker 模式(fail-open)
- 新项目(contract-version ≥ 6.11.0):SessionStart 检测到 lock 存在且 pid 存活 → 强制 worker 模式(fail-closed)
- 若 SessionStart hook 异常失败:fail-open 走单会话路径,Doctor 输出 WARN("SessionStart hook 异常,多会话隔离失效")
- 与 D-028 §9 迁移宽限期范式一致
