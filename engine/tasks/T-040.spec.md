# T-040.spec — 小任务 progress.md 豁免条款 + v6.11.3 patch

> Spec for T-040. Source of ACs. Do not edit task card header without updating this spec.

## 背景与动机

T-039(v6.11.2 patch)的归档 progress.md 实际写成 4 栏自创格式:
- §1 Goal
- §2 Current Step
- §3 Done
- §4 Next AC

而契约 FILE 13 规定的 7 栏是:
- §1 已读文件(理解项目)
- §2 已确认接口(不重复读)
- §3 已排除路径(原 TRAIL 的家)
- §4 当前进行到(压缩恢复点)
- §5 待确认问题
- §6 已知风险/未解 bug
- §7 回滚尝试

漂移根因:小任务(estimated_steps ≤ 10 + checkpoint_plan=inline + AC ≤ 7 + 单 commit)通常没有"接口确认""路径排除""待架构师回复""已知 bug"等可记录的中途决策,强制 7 栏产出空栏噪声淹没信号,违反 D-028 §6「机制错配」原则。agent 自觉不写空栏 → 偏离合同 → 契约与实际漂移。

## 设计目标

把"小任务确实不需要 7 栏事件驱动"正式化为契约条款,而非继续依赖 agent 自觉偏离合同。

## 豁免条件(必须同时满足)

1. `estimated_steps ≤ 10`
2. `checkpoint_plan = inline`(或架构师显式声明的等价 bypass 值)

两者 AND 关系,缺一不可。`tryout` 不算豁免,因为 tryout 是"试错卡",可能仍然复杂(如 T-036 estimated_steps=18)。

## 豁免范围

- 7 栏骨架结构不变(`engine/skeleton/progress.md` 不改),单一来源
- 事件驱动更新触发点降级为:**仅 §1 + §4 必填**
  - §1(已读文件)— 至少读了任务卡本身和契约源,触发"每读完一个文件后追加"
  - §4(当前进行到 / 压缩恢复点)— 触发"跑完一个 AC / 状态切换时"
- §2/§3/§5/§6/§7 — 可留空,或写单行 `n/a (small task exempt)` 占位(避免被误判为缺失文件)
- 不豁免生命周期(归档逻辑不变)、不豁免 SessionStart 注入(仍注入 §1~§7 全文)、不豁免 Doctor 检查存在性

## 边界

- estimated_steps > 10 或 checkpoint_plan 非 inline → 仍按完整 7 栏事件驱动,无豁免
- 7 栏骨架文件不改
- Doctor 不增减检查逻辑(豁免由 agent 自觉 + 契约文本约束)
- migrator managed block 不新增(没有 4 栏到 7 栏的迁移需求,豁免前后都用同一骨架)

## 狗粮

本任务 T-040 自身满足豁免条件(estimated_steps=6, checkpoint_plan=inline),其 progress.md 应仅填 §1 + §4,§2/§3/§5/§6/§7 写 `n/a (small task exempt)` 占位。
