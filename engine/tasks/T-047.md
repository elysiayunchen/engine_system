# T-047: 修复 Windows PS 5.1 compat check 失败 — engine.ps1 + engine-verify.ps1 字符串字面量非 ASCII 字符

> status: done | lane: engine-runtime | decision: none | plan: none | domain: engine-runtime,root
> estimated_steps: 5 | checkpoint_plan: inline (patch 任务,4 AC,改动集中)
> depends-on: none

GOAL: 修复 GitHub Actions CI Windows job 持续红灯——`check.ps1` 的 "Windows PowerShell compatibility" 步骤使用 `powershell.exe` (PS 5.1) 的 `Parser.ParseFile()` 解析所有 .ps1 文件。PS 5.1 对无 BOM 的文件使用系统默认 codepage (Windows-1252) 读取,而非 UTF-8。两个文件的**字符串字面量**含非 ASCII 字符,其 UTF-8 字节序列中包含 0x94 (Windows-1252 左弯引号 `"`),被 PS 5.1 误认为字符串终止符,导致 parse 失败:

1. **engine/bin/engine.ps1 L537**: `Write-Host "Flag file does not exist — multi-session lock already enabled."` — em-dash `—` (U+2014) UTF-8 = `E2 80 94`,byte 0x94 = `"` in Windows-1252。
2. **engine/scripts/engine-verify.ps1 L117**: `$header = "...AC 级压缩恢复锚点,见..."` — Chinese char `锚` (U+951A) UTF-8 = `E9 94 9A`,byte 0x94 = `"` in Windows-1252。
3. **engine/scripts/engine-verify.ps1 L122**: `$line = "...— evidence/..."` — em-dash `—` 同 #1。

修复方案:将字符串字面量中的非 ASCII 字符替换为 ASCII 等价物(em-dash → ASCII hyphen,Chinese → English)。注释中的非 ASCII 字符保留不动(PS 5.1 跳过注释字节,不影响 parse)。install.ps1 (ASCII-only) 和 engine-doctor.ps1 (非 ASCII 仅在注释 + § 安全字符) 已 PASS,证明方案有效。
