GOAL: 修复 GitHub issue #14 [D-12] — Evidence JSON schema 跨版本字段名不一致 (`verdict` → `status`)。核查发现 issue 描述的 `verdict` 文件场景在仓库内不存在,但有三个真实隐患:(A) bash 与 PowerShell 大小写敏感不一致;(B) 契约缺 AC-N.json 正式 schema 块;(C) 下游项目可能有旧 `verdict` 文件需向后兼容读。本次全修。

## 问题清单

### #14 (D-12) P2 — Evidence JSON schema 不一致
- **隐患 A(大小写不一致)**:
  - `engine-doctor.sh:1263` `grep -Eq '"status"[[:space:]]*:[[:space:]]*"pass"'` 无 `-i`,只认小写 `pass`。
  - `engine-doctor.ps1:1258` `$evContent -notmatch '"status"\s*:\s*"pass"'` PowerShell `-notmatch` 默认大小写不敏感,接受 `PASS`。
  - `githooks/pre-commit:290` 同 .sh 行为(无 `-i`)。
  - 影响:bash 与 ps1 行为不一致,跨平台回归风险。
- **隐患 B(契约缺 schema)**:`contract/src/30-operational.md` 有 DEAD-CODE.json schema 块(L226-258),但无 AC-N.json schema 块。schema 仅由 `engine-verify.{sh,ps1}` 写入器事实标准定义,契约层无单点真相。
- **隐患 C(下游 `verdict` 兼容)**:issue 描述的下游项目可能有旧 `verdict: PASS` 文件,doctor 不识别会误报 missing。
- 修复:契约补 AC-N.json schema 块(明确 `status` 字段,显式声明 `verdict` 不被识别但 doctor/hook 加向后兼容读 + WARN);bash grep 加 `-i` 与 ps1 行为对齐;`check_legacy_data_format` 加 `verdict` 字段 WARN。
