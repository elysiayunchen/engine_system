AC-4: model_id 被动记录 — PROVE.json 和 REVIEW.json 的 write_provenance 含 "model_id" 字段（自报，不排名，可为空）
  verify: bash -c "grep -q 'model_id' $CLAUDE_PROJECT_DIR/engine/scripts/engine-prove.sh"

AC-5: 同/异审查标记 — validate 时比较生成者 model_id 与审查者 model_id，不同则 REVIEW.json 含 "cross_model": true
  verify: bash -c "grep -q 'cross_model' $CLAUDE_PROJECT_DIR/engine/scripts/engine-review-agent-validate.sh"

AC-6: 全量回归 — prove-infer + prove-execute + review-validate + grounded 四套件 0 failed
  verify: bash -c "bash $CLAUDE_PROJECT_DIR/tests/workstream/test_prove_execute.sh 2>&1 | grep -q '0 failed'"

## CONSTRAINTS

- 不做模型排名/分级，model_id 纯被动记录
- 多视角是同模型不同 prompt，不强制跨模型调用
- AC 交叉锚定只检查文件/pattern 级覆盖，不做语义等价判断
- 成本增量控制在 review 阶段 2-3x tokens 以内，不影响 infer/execute 主路径
- 不改 contract（budget 满），以 convention 层落地
